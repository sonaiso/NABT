# تصحيح حدود السؤال والشهادة بعد مراجعة #3

هذه حزمة إصلاح `0.5.0a2` فوق الإيداع
`b6ba0c6d960a3627d2841955fa8aeb369d54794c`. تعالج العيوب الخمسة التي أبلغت
عنها مراجعة #3: سياق العلاقة في السؤال، وربط القاعدة بعبارتها، وحدود
التعويض، وإلزام شهادة تخص السؤال، وفشل فحص الشهادات المشوهة.

## إثبات وجود العيوب قبل الإصلاح

[`baseline_reproductions.py`](baseline_reproductions.py) هو برنامج إعادة
الإنتاج الذي شُغّل على أرشيف الإيداع السابق، ونتيجته محفوظة حرفيًا في
[`baseline_results.json`](baseline_results.json). قبل الإصلاح:

- قُبل مصدر العلاقة، وفشل السؤال عنه بـ`INVALID_QUERY`.
- قبل الفاحص المستقل القاعدة بمقطع حرف واحد صحيح البصمة، وبمكونات ناقصة
  أو معكوسة أو مكررة، وقبل تعويض الثابت `ريان` بـ`أثير`.
- ظلت بوابة القياس ناجحة بالأعداد المنشورة نفسها بعد حذف شهادة جواب
  مؤيد، أو استبدالها ببرهان مقدمته، أو تسميتها `signed` فقط.
- شهادة مشوهة في حالة `s03` غير المغطاة أصلًا رفعت `KeyError`، ومع ذلك
  بقي علما سلامة الاعتماد والشهادة صحيحين.

هذه تحويرات موضعية عند حدود الإعادة، وليست ادعاء أن التنفيذ غير المعدّل
كان يصدر تلك الشهادات المحرفة تلقائيًا. فاحص النواة الإنتاجية **رفض**
شاهدي تحريف العبارة وتعويض الثابت. راجع
[التقرير المستقل](../../../docs/PR3_REPLAY_BOUNDARY_REVIEW.md) لفصل النتيجتين.

الإيصالان الجديدان في
[`previous-runtime-v2/receipt.json`](release/previous-runtime-v2/receipt.json)
و[`arabic-regression/receipt.json`](release/arabic-regression/receipt.json).
اجتازت الشهادات الأصلية السليمة الفاحص الأقوى في الحالتين. رفض التحويرات
ثابت بالاختبارات الإضافية. أصل العينة لم يتضمن سؤال العلاقة الكاشف للخلل؛
لذلك لا يدل ثبات الأعداد على أن الإصلاح بلا أثر، ولا يجيز عد اختباره
الجديد زيادة في مقام العينة القديمة.

للمصدر `علاقة يراجع. سالم يراجع تقرير.` صار السؤال المباشر `SUPPORTED`،
وعكس الطرفين `UNKNOWN`، والسؤال عن النفي `REFUTED`. تسحب القرينة بسحب آخر
تصريح فعال، وتبقى معزولة بالنطاق. المثال مثبت أيضًا من الحزمة المثبتة.

## الهويات الجديدة وحدودها

- الحزمة: `0.5.0a2`؛ القارئ: `nabt.arabic-reader.v2`؛ قانون اللغة بقي
  `nabt.arabic-syntax.v1`.
- الفاحص: `nabt.arabic-syntax.independent-evaluator.v2`.
- [تجميد التنفيذ](code_freeze_v2.json): 30 ملفًا، وبصمة الجرد
  `202df9bbc9e450fa110c7e497cffd50b0b70a03b8b3c5017f9d49793ff6ec85f`.
  [الأرشيف](code_freeze_v2.tar.gz) يحفظ بايتاتها.
- [سجل العبارات والأدوار](statement_oracle_v2.json): 65 سجل مصدر و52 عبارة
  دلالية مسندة، وبصمته
  `73c232127ce3da747b54face3f508273e3730be37a89522dceec4d5446cbd0bd`.

بُني سجل العبارات من نص المرجع المنشور وتفسيراته السابقة، دون اشتقاق
المتوقع من خرج القارئ أو شهاداته. أضيف بعد التجربة الأولى، وخضع لمراجعة
وكلاء منفصلة؛ ليس مادة محجوبة جديدة ولا مراجعة خبير لغوي بشري.

الفاحص يعيد بناء الإغلاق الموقع والنظيف من جميع القضايا المرجعية للمصادر
الفعالة؛ لا يعتمد على المقدمات المختارة داخل الشهادة وحدها لكشف التعارض.
حده 100,000 تعيين للقاعدة؛ تجاوز الحد يفشل الفحص. يجب أن يطابق التعويض
متغيرات الجسم بالضبط، وأن يستند كل رأس إلى متغيرات جسمه، وأن تبلغ
الخاتمة السؤال المتوقع أو نقيضه بحسب خانة الشهادة وحالة الحكم.

لا يمنح `analysis_id` سلطة: يبقى وصفًا داخليًا معتمًا للقارئ. يُفحص ارتباطه
الحسابي بـ`clause_id`، ولا يعيد هذا الفاحص اشتقاقه من خوارزمية القراءة.
فحص الشهادات الدلالية هنا لا يحل محل إعادة تنفيذ إيصال `Program` كاملًا
عبر `verify-run`، ولا يثبت صدق المصدر في العالم أو صحة كل تحليل للعربية.

## إعادة التشغيل

```sh
make check LAKE=/path/to/lean-4.34.1-linux/bin/lake
```

ولإعادة قياس التنفيذ الأول بالفاحص الحالي:

```sh
python -I evidence/arabic_syntax/review_fixes/replay_previous_runtime.py \
  --baseline-root /path/to/extracted-b6ba0c6-checkout \
  --output-dir /tmp/nabt-previous-runtime-new-run
```

يتحقق البرنامج من تطابق ملفات التنفيذ السابق الثلاثين مع التجميد الأول،
ويستوردها وحدها مع أدوات الفحص الحالية. يرفض الكتابة داخل المصادر أو
الدليل المنشور أو فوق مخرجات موجودة. نُسخت النتائج إلى هذه الحزمة للنشر
بعد اكتمالها. لم يُغيّر شيء في `independent/` أو التجميد الأول أو
`release/` السابق أو دليل `text_inquiry` التاريخي.
