# دليل تشخيص الاستعمال الطبيعي

- `benchmark_before.json.gz`: تشغيل حقيقي للقارئ v1 على الأب
  `c3b92effb544da6207d30079a82e9c980ddf817f` قبل تعديل القارئ: 19/11/14.
- `benchmark_after.json.gz`: التشغيل الحقيقي بعد التصحيح المنفي المحدود:
  20/10/14؛ M05 وحدها انتقلت من الفشل إلى النجاح. يحفظ التقرير جميع
  الطلبات والأجوبة والنتائج وبصمات الشفرة والمصادر والمدقق، لا ملخصًا فقط.
- `measurement.json`: المقامات المرحلية، والتغير، والتشخيص الأصلي للحالات
  الإحدى عشرة. الطبيعي بقي 0/6، ولا يعني نجاح بوابة التنفيذ نجاح أمثلته.
- `native-conformance.json`: 786 مقارنة فعلية بين الفاحص الأصلي والمحول،
  دون اختلاف. هذا توافق محدود وليس مبرهنة تكرير Python.
- `vowelized_controls.json.gz`: شاهد مشكول ناجح، وضابط ينفي المعنى نفسه
  ويثبته فيعيد تعارضًا دون شهادة قبول. التنفيذ محلي أصلي، لا اختبار موقع حي.
- `security-review.json`: إعادة الضوابط المستقلة السابقة، 46/46. إعادة
  التنفيذ ليست مراجعة جديدة مستقلة للتعديل.
- `code_manifest.json`: بصمات الملفات والمصدر المعني قبل تسليم التعديل.
- `validation.json`: الفحوص المحلية المنجزة وحدودها.
- `full-unit-result.json` و`full-unit-log.txt.gz`: التشغيل الشامل المنظم؛
  2263 حالة منفذة، منها 2235 ناجحة و28 متخطاة، دون إخفاق أو خطأ. يحتوي
  السجل لقطة مكدس دورية أثناء فحص بصمة الملف التنفيذي؛ ليست مهلة أوقفت
  الاختبارات، وانتهى التشغيل كاملًا برمز خروج صفر.
- `deployment_readiness.json`: لقطة خطة النقل؛ لا تغيير في الموقع، وتبقى
  هوية الرأس الذي تخصه فحوص GitHub صريحة. نجاح رأس سابق لا يفحص رأسًا جديدًا.

التقرير المضغوط UTF-8 JSON، gzip قابل لإعادة الإنتاج (`mtime=0`). لا
تتضمن الحزمة اعتماديات أو بيانات وصول. مرجع الحالات المجمد هو
`evidence/linguistic_truth_v1/benchmark_gold.json` وبصمته محفوظة في كل تقرير.
لا تغير الخطة المرجع ولا تستعمله تدريبًا محجوبًا. خطوات إعادة القياس
وتشخيص كل حالة في `docs/NATURAL_USE_GAP_AR.md` وخطة النقل والتراجع في
`docs/LEXICAL_DEPLOYMENT_PLAN_AR.md`.
