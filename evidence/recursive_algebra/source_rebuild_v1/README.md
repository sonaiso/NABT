## ما يشمله البناء وما يبقى خارجه

الجذر النشط في Alghanem هو `formal/a116`. الملفات الثمانية في `suspended/samai/lean` ليست ضمنه؛ يعلن المستودع نفسه أن مصادر QAC وArramooz وOpenITI المتعلقة بها لم تمر ببوابة المصدر وختمه، وأن البراهين تخص جداول جلسة. جرى التحقق من هويتها فقط، ولم يمنحها هذا البناء اعتمادًا معجميًا جديدًا. راجع `suspended_source_status.json`.

الملفات الأربعة التاريخية في `NABT/evidence/...` هي لقطات قبل/بعد محفوظة وليست أهدافًا للمشروع النشط. أما `Audit.lean` في كل مشروع فشغّل مباشرة بعد البناء، لذلك لا يعني ظهوره في `not_default_build_outputs` أنه لم يفحص. وينطبق الفصل نفسه على ملفات التصدير الستة التي يثبت سجلها الإضافي ترجمتها. و`formal/lakefile.lean` في NABT إعداد يفسره Lake، لا وحدة عادية تحت `lib/lean`.

لا تشمل هذه الجولة إعادة استخراج المدونات أو جميع اختبارات Python أو بوابات النشر الخارجية، ولا جردًا حديثًا لكل حسابات المستخدم الخاصة والعامة. لا تحول صحة المبرهنة المشروطة أو اكتمال المجال المولد إلى نجاح اكتساب الأصناف أو الأصول من العربية الحرة.

## إعادة الفحص

استخدم Lean/Lake بالإصدار المثبت في `lean-toolchain` لكل مشروع: `leanprover/lean4:v4.34.1`؛ الإصدار الذي نفذ هنا يحمل إيداع Lean `5045d0056413266e57c625dcd7c365b10e377c52`. الأوامر الدقيقة وتوقيتها محفوظة في سجلات JSON. مثال إعادة جلب إيداع مثبت ثم بناء المشروع:

```sh
git init SOURCE_COPY
git -C SOURCE_COPY remote add origin https://github.com/OWNER/REPOSITORY.git
git -C SOURCE_COPY fetch --depth 1 origin PINNED_COMMIT
git -C SOURCE_COPY checkout --detach FETCH_HEAD
git -C SOURCE_COPY rev-parse HEAD
git -C SOURCE_COPY rev-parse HEAD^{tree}
cd SOURCE_COPY/LEAN_PROJECT_ROOT
LEAN_NUM_THREADS=1 lake --no-cache build
LEAN_NUM_THREADS=1 lake env lean Audit.lean
```

استبدل المالك والمستودع والإيداع وجذر المشروع بالقيم في الجدول والسجلات. استعمل نسخة معزولة جديدة ولا تنشئ ناتج البناء في المستودع المرجعي. في بيئة محدودة الذاكرة قد تحتاج إعادة أمر البناء بعد تسجيل أي نفاد للموارد؛ غياب اكتمال البناء ليس حكمًا لغويًا.
