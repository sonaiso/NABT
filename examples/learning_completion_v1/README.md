# حزمة لتجربة مقيّم المعايير

`measurement_fixture.json` سبع حالات مؤلفة لاختبار أداة القياس. نصوصها
ومعرفات قراءاتها وأجوبتها صناعية، ولم ينتجها V14. ليست بيانات ذهبية
للعربية أو عينة من العالم. تشترك الحالات في مصدر واحد؛ لذلك يعيد
المقيّم مجموعة استقلال واحدة، ولا يمنحها بوابة تعميم إحصائي.

تتطابق أجوبتها المودعة مع مرجعها؛ فيجتاز **اتفاق المرجع**، وتبقى
**شهادة المسار المرخص** غير مقيسة. كما تبقى أرضية التدريب غير مكتملة
لأن لكل نوع مجموعة تدريب ومعايرة واحدة فقط. أزواج التدخل توافق مرجعها؛
ذلك لا يثبت أن محركًا سحب شاهدًا أو أعاد ترقيم A116 فعلًا.

```bash
export PYTHONPATH=src:.
python -m tools.lexical_training.completion_criteria \
  --benchmark examples/learning_completion_v1/measurement_fixture.json \
  --benchmark-sha256 096614088c0e92e323cded9eec7b6f3aae3b8d47c683cd923ed678b41cb3306a \
  --output /tmp/completion-fixture.json
```

البصمة المعتمدة للملف هي محتوى `measurement_fixture.sha256`؛ يُضبط
الأمر أعلاه مع البايتات المثبتة في الإصدار. يمكن للمطور تغيير نتيجة
سالبة إلى قبول أو إسقاط قراءة بديلة في نسخة تجريبية، وحساب بصمتها
قبل التشغيل، ليرى فشل بوابة المعيار. تغيير المرجع أو أهدافه يعني
مجال تقييم آخر؛ لا يجوز تغييرهما لإعادة تسمية فشل الاختبار نجاحًا.

في تجربة فعلية يجب أن يأتي المرجع من مراجعة مستقلة ومصدر معلوم، وأن
تُحفظ بصمته قبل فتح الاختبار، وأن تعاد تنبؤات النموذج وأعمال الملاك
عند القياس. البرنامج يفحص البايتات نفسها التي يحسب بصمتها؛ لكنه لا
يستنتج استقلال المراجع أو تاريخ إغلاق الاختبار من البصمة وحدها.
