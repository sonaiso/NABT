# مسار القراءة والتنفيذ المتحقق

هذه الإضافة تغلق وصلة تنفيذ محددة في `nabt.verified-ground-reading.v1`:
النص الأصلي ← قراءة ضمن لغة مضبوطة ← دلالة القضايا والقواعد ← نتيجة الاستدلال.
لا تغلق كل المسار اللغوي في PR #17، ولا تثبت اكتمال العربية أو تنقيح جميع
برامج Python إلى Lean. المسار الجديد اختياري، ولا يغير نتائج القارئ السابق.

## العقد

تدعم اللغة قضايا أرضية موجبة وسالبة من الشكل `سالم هو حكيم` أو `سالم يحب سهيل`،
وقواعد أرضية من الشكل `إذا سالم هو حكيم فإن سالم هو عالم`، مع ` و ` بين مقدمات
كاملة. كل عبارة تنتهي تحديدًا بنقطة ثم LF؛ السؤال مستقل من الشكل
`هل سالم هو عالم؟` ثم LF. `ليس ` تسجل القطب السالب للقضية الكاملة؛ تحفظ الأقطاب المتعارضة دون
استنتاج كل شيء منها. الأسماء رموز معتمة من
المجالات الحرفية المنشورة في `validName`، والكلمات المحجوزة ممنوعة كأسماء.
لا يوجد تطبيع أو تجاهل للمسافات أو تغيير للتشكيل أو ترتيب أطراف العلاقة.

لا يشمل العقد المتغيرات، والتعريفات، والضمائر، وحل الإحالة، وأسئلة WH،
والتراكيب الحرة، ولا يثبت الدلالة المعجمية لاسم مثل «حكيم». خارج هذه اللغة
يمتنع مقترح الشهادة؛ لا يعد الامتناع حكمًا ببطلان العربية المدخلة.

## كيف يصل البرهان إلى التنفيذ

- يستخدم `tools/verified_reading.py` قارئ NABT الحالي لاقتراح قراءة وشهادتين
  للاستدلال. هذا البرنامج غير موثوق لإسناد الأحكام؛ ناتجه وحده ليس شهادة مقبولة.
- يقرأ `verifiedReading` في Lean ملفات المصدر والسؤال مستقلة عن ملف الشهادة،
  ويقرأهما بقارئ Lean حتمي مستقل عن مقترح Python وعن العارض، ثم يقارن
  البايتات كاملة بإنتاج القواعد المصرح بها. يلزم تطابق هوية المصدر
  ومراجعته ونطاقه وبايتاته، والسؤال نفسه، ولا يستبدلها بحقل SHA أو `verified`.
- يعيد Lean كل خطوة من الصفر باستخدام `SemanticInference.replay`. ثم يفحص
  انغلاق القائمة تحت **جميع** الوقائع والقواعد، حتى التي لم ترد في المسار المقترح.
  لذلك لا يكفي حذف خطوة أو نتيجة للحصول على `UNKNOWN`.
- يبني النظرية الخالية من المقدمات المتعارضة وفق `cleanProgram` الموجود، ويفحص
  شهادة إغلاقها أيضًا. يستخدم الحالات الموجودة: `SUPPORTED` و`REFUTED`
  و`CONFLICT` و`UNKNOWN` و`DEFER` عند الاستدلال المتأثر بالتعارض.
- `execution_exact` يثبت التطابق في الاتجاهين بين بتات النتيجة والاشتقاق.
  `lowering_preserves_meaning` يربط الدلالة التركيبية للقضايا والقواعد بالاستدلال؛
  و`source_to_execution_entails` يصل من دلالة بايتات المصدر مباشرة إلى الجواب
  المشتق؛ وتثبت `reading_unique` فرادة القراءة المقبولة في هذا المجال.
  `unknown_has_no_derivation` يثبت غياب الاشتقاق للقطبين عند غياب الدعم.

هذه سلامة بالنسبة إلى **نظرية المصدر**. إذا قال المصدر شيئًا غير صحيح في
العالم، لا تحول المطابقة النصية ذلك إلى حقيقة. صحة النسخة، ونسبة الكتاب،
وتفسير اللغة الطبيعية، وملاءمة المرجع العام تحتاج أدلة منفصلة.

## التشغيل

باستخدام سلسلة الأدوات المثبتة في `formal/lean-toolchain`:

```sh
make formal
PYTHONPATH=src python tools/verified_reading.py \
  examples/verified_reading/source.txt examples/verified_reading/query.txt \
  --output artifacts/local/verified-reading/certificate.json
formal/.lake/build/bin/verifiedReading \
  examples/verified_reading/source.txt examples/verified_reading/query.txt \
  artifacts/local/verified-reading/certificate.json text 1 default
make verified-reading-conformance
```

المخرج المتوقع للمثال هو `verified=true` و`status=SUPPORTED` مع النص والسؤال
المطابقين. فشل الشهادة أو نفاد الموارد لا ينتج حالة لغوية؛ يخرج `verified=false`
وحقل `error` دون `status`. تختلف أخطاء الإدخال والموارد وIO. الحدود الحالية:
65536 بايتًا للمصدر، 8192 للسؤال، 1 MiB للشهادة، 256 عبارة، 16 مقدمة، و512
عنصرًا في كل سجل اشتقاق/نتائج. تجاوز الحدود ليس دليلًا سلبيًا.

## حدود الثقة والاكتمال

البرهان يخص تعريفات Lean الكلية التي ينفذها المدقق، مع نواة Lean والمكتبة
والترجمة وبيئة التشغيل وقراءة الملفات وفك JSON ضمن قاعدة الثقة المعتادة.
ليس برهانًا على شفرة الآلة أو نظام التشغيل. حراسة JSON والميزانيات مفحوصة
تنفيذيًا؛ ليست لها هنا مبرهنة تنقيح مستقلة. مطابقة كل البايتات داخل المدقق
تمنع فك JSON أو مقترح Python من استبدال قراءة مقبولة بنص مختلف.

`Reads` يحدد المجال بإنتاج اللغة المضبوطة الصريح. لا ندعي برهان شمول محلل
Python لكل نص مقبول، ولا تنقيح قارئ PR #17 الحر. فرادة القراءة مثبتة للمسار المضبوط الجديد،
ولا تنتقل إلى العربية الحرة. قبول شهادة يثبت النتيجة داخل هذا المجال؛ فشل اقتراحها لا يثبت عدم
وجودها. لا تُرقّى `strict_complete_pass` أو `acquisition_measured` أو أي
قياس سابق بهذه الإضافة.

## التحقق

تضيف الوحدة ثلاث عشرة مبرهنة إلى سجل التدقيق. تشمل اختبارات التنفيذ جميع الحالات
الخمس، وسلامة ترتيب أطراف العلاقة، والنفي، والقواعد متعددة المقدمات، والدورات
بلا وقائع، وتحريف البايتات والهوية والمراجعة والنطاق والسؤال، وحذف اشتقاق
أو تعارض، وتزوير الفهارس وحقل السلطة، وحدود الموارد. مرجع مستقل يعد كل
التفسيرات المنطقية لـ31 برنامجًا صغيرًا و93 سؤالًا، بدل نسخ خوارزمية الإغلاق.

تفصل نتيجة التحقق المحلي المسجلة في `evidence/verified_reading/VALIDATION.json`
عن GitHub Actions. لا تعني إضافة خطوة CI أن تشغيلها البعيد قد نجح.

## ما يلزم للإغلاق العام

يبقى نقل هذا العقد إلى قارئ PR #17 متعدد القراءات عملًا مستقلًا: تمثيل كل
القراءات المرخصة ونقصها في Lean، والتحقق من الإحالة والتقييدات الزمنية
وأدوار العلاقات من المصدر، وإثبات التعويض للمتغيرات والتعريفات، ثم ربط
ذلك بقرائن المعجم والبنية العودية. يجب أن يستمر التعليق عند غياب شاهد،
وأن تشمل الاختبارات قراءات متعارضة وأدلة مسحوبة؛ لا يكفي نجاح مسار واحد
لتغيير دعاوى الاكتمال المنشورة.
