- الوصول الحالي: `custom`، مستخدم واحد، دون مجموعات أو زوار خارجيين.

- آخر إيصال معجمي حي محفوظ في المستودع مرتبط بمشغّل

## مساران بإطلاقين منفصلين

**الإطلاق A: خانات معجمية مرتبة**. واجهة جديدة تطلب `slots` صراحةً،
وتعرض القراءات الـ42، وتعيد تشغيل Lean لفحص أهداف الخانات وتركيبها.
لا تسمى محلل نص حر. عرض اختيار «عين» وخمس قراءات لا يرفع نتيجة 0/6.

**الإطلاق B: قارئ الاستعمال الطبيعي**. لا يفتح قبل جسر الوقوع والمعجم
والنطاق والقرائن والتقييم المستقل في [خطة سد الفجوة](NATURAL_USE_GAP_AR.md).
قانون الاكتساب v2 المعدل محليًا ليس مفعّلًا تلقائيًا في الصفحة.

## العمل المطلوب وبوابات قبوله

| المرحلة | الملفات/النظام | شرط المرور |
|---|---|---|
| تثبيت نسخة الإصدار | فرع التكامل، سجل الأدلة | SHA واحد للمرشح؛ شجرة نظيفة للأجزاء المنشورة؛ لا نسخ من ملفات محلية غير متتبعة |
| تحقق المستودع | `make check` والبوابات المستقلة | اكتمال جميع الوظائف المطلوبة على SHA نفسه؛ لا اعتماد نجاح رأس أقدم أو وظيفة ما زالت جارية |
| مصدر الكتالوج | `fetch_lisan_source.py` و`build_lexical_completion.py --check` | استعادة لسان العرب المثبت وإعادة كل الاقتباسات؛ المصدر المفقود فشل جاهزية ظاهر |
| المشغّل | `tools/proof_lab.py` و`.github/workflows/proof-lab.yml` | إضافة `mode=lexical_completion` بعقد مستقل، وبناء الفاحص الجديد، وحفظ الطلب والجواب والبصمات ضمن النقل المشفر |
| التحقق في الخادم | `integrations/proof_lab/site/worker/server.mjs` | رفض البُعد/العدد غير الصحيح والمفاتيح الزائدة والتناقضات؛ ربط SHA الطلب والفاحص والكتالوج وSHA الشفرة بإيصال التشغيل |
| واجهة المستخدم | `web/app.js` و`web/index.html` | إدخال خانات، عرض البدائل والحدود والمصادر، وتركيز لوحة المفاتيح محفوظ عند اختيار طبقة أو دعوى |
| توافق المسارات | اختبارات Python وNode | الاستدلال والتقييم والشهادة السابقة لا تتراجع؛ المسار الجديد لا يغيّر إحصاء القديم |
| معاينة معزولة | نسخة محلية ببيئة اختبار | نجاح الرحلة من طلب إلى إيصال أصلي؛ لا خلط إيصال تجريبي بالحي، ولا أسرار في المتصفح |
| جاهزية التراجع | نسخة الموقع والإعدادات | استعادة النسخة 7 ومرجع المشغّل المتوافق مجربة؛ حفظ تذاكر الطلبات الجارية وتحديد مصيرها |
| نقل مضبوط | Sites ومرجع المشغّل | تفعيل الزوج المتوافق من مصدر الموقع وSHA المشغّل بعد إيقاف الطلبات الجديدة مؤقتًا |
| قبول حي | طلبات اختبار معلنة | فحص عبر API المنشور، ثم اختبار متصفح لوحة المفاتيح؛ تظهر حالة Lean الفعلية لكل نتيجة |

فاحص المستقبل في الخادم يجب أن يقبل **إيصال فشل صالحًا** بلا payload خاص
بـbenchmark، ويميزه من إيصال تالف. كما يرفض `native_checked=false` المصاحب
لدعوى شهادة متحققة. لا يحوّل `native_checked=true` إلى «كل الأهداف مرخصة»:
قد يفحص Lean عدم الترخيص أو نفاد الموارد أو معنى غير مفسر.

لا يُخفى حد التركيبات 512: أربع خانات «عين» تنتج 625 احتمالًا وتعيد
`RESOURCE_EXHAUSTED`، لا فحص بادئة ناجحًا. يجب اختبار أحجام ردود الاقتباسات
والتشفير وضغط الأثر وحدود Worker الفعلية، وعدم تكبيرها بلا قياس.

## مصفوفة قبول الإطلاق A

| الطلب أو الحد | المنتظر |
|---|---|
| ذهب/ولد وأهداف التعريف المثبتة | `CONDITIONAL_ALL_READINGS` مع تنفيذ Lean فعلي |
| عين ← النقد | خمس قراءات و`CONDITIONAL_SOME_READINGS` |
| عين + قلم | 15 تركيبًا محفوظًا؛ لا اختزال مبهم للبدائل |
| شمس ← النهار | `UNMEASURED_DEFINITION`؛ لا اختراع لازم |
| بحر ← ماء | `UNMEASURED_ENTRY`؛ لا مساواة المجهول بالكاذب |
| أربع خانات عين | `RESOURCE_EXHAUSTED` بلا دعوى اكتمال البحث |
| مصدر أو ملف تنفيذي مفقود | فشل تحقق صريح مع `native_checked=false` |
| شهادة قديمة/طلب معدل/رأس غير مطابق | رفض الربط؛ لا إعادة استخدام نجاح مخزن |
| عدد Boolean أو عشري غير صحيح، تكرار حقل | رفض إدخال دون تحويل عددي فاقد |
| فشل Actions أو إلغاء الطلب أو غياب الأثر | حالة تشغيل صريحة دون شارة «Lean متحقق» |
| تبديل الطبقات والدعاوى بلوحة المفاتيح | التركيز يعود إلى العنصر المقصود ولا يسقط إلى الصفحة |

الضوابط المعجمية اليدوية الـ16 تحقق العقد المحدود؛ تضاف ضوابط النقل
والتوافق والواجهة. لا تُجمع أعداد هذه الاختبارات في نسبة لغوية واحدة.

## إجراء النقل والتراجع

1. ثبّت SHA مرشح نهائيًا، وأعد فحص الوظائف والأدلة على هذا الرأس بعد
   اكتمالها؛ احفظ معرفات التشغيل والاستنتاجات، بما فيها التخطي المعلن.
2. احفظ نسخة الرجوع، وSHA مصدر الموقع ومرجع المشغّل ونسخة إعداداته
   **دون قيم الأسرار**. أعد قراءة النشر النشط؛ أحدث نسخة محفوظة قد لا
   تكون النشطة عند التنفيذ الفعلي.
3. جهّز مصدر الموقع المتوافق في مستودع Sites بعد نجاح المعاينة، وأغلق
   إنشاء الطلبات الجديدة فترة التبديل. أنه الطلبات الجارية أو أظهر
   بوضوح إلغاءها؛ لا تتجاهل اختلاف SHA في تذكرة قديمة.
4. حدّث مرجع المشغّل و`NABT_CODE_SHA` ونسخة الموقع كزوج واحد أثناء إغلاق
   الإدخال، ثم أعد فتحه. احتفظ بالمسارات القديمة، مع فصل المسار الجديد
   في الواجهة. لا تجرى هذه الخطوة تلقائيًا بانتهاء CI وحده.
5. نفّذ عينات القبول الحية أعلاه على نصوص الاختبار فقط، واحفظ رقم الطلب
   وبصمة النص والكتالوج والمدقق وSHA الشفرة ومعرف تشغيل Actions؛ لا
   تحفظ المفتاح أو تذكرة الوصول. افحص الواجهة فعليًا بعد فحص API.
6. إذا خالف أي إيصال العقد، أو تسربت بدائل بين الخانات، أو ظهر تعارض في
   الهوية أو الوصول: أغلق الإدخال الجديد، وأعد النسخة 7 **وإعدادات
   المشغّل المتوافقة معها**، ثم شغّل شاهد الشهادة القديم. لا يكفي
   الرجوع إلى HTML قديم مع إبقاء مشغّل جديد غير متوافق.

المراقبة في الإصدار الأول: عدد نجاحات النقل وإخفاقاته، زمن التنفيذ
والانتظار، حدود الرد، حالات نفاد الموارد، وحالات عدم توافق الشهادة.
حالة اللغة المجهولة لا تعد عطل نقل. لا تُستخدم نصوص المستخدمين في
التدريب تلقائيًا، ولا يتغير جمهور الموقع أو يُدّعى تقييم التواتر.
