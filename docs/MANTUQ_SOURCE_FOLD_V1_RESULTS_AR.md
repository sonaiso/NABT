# نتائج وصلة المصدر والاستدلال والطي

## نطاق الدفعة

نُفذت الوصلة في فرع مستقل من `main` عند
`cebb5c472451a1d541ed9b93f56bb6cd2e9d606e`. بقي فرع PR65 والمستودع
الأصلي وتعديلاته البحثية محفوظة. يشرح
[دليل التشغيل والعقد](MANTUQ_SOURCE_FOLD_V1_AR.md) حدود المدخلات
والنتائج والمجال العددي. لا توجد تغييرات في `formal/` أو `src/`،
ولا مبرهنة أو قانون لغة جديد في هذه الدفعة.

المسار المعتمد هو:

1. قراءة المصدر والسؤال فعليًا بواسطة `explainable_pilot` v2 والفاحص الأصلي.
2. تعيين قاعدة المصدر بمقطعها، وحمل جميع الشواهد الموقعة إلى المقيم المؤهل.
3. إبقاء المتطلب المشتق من أصل متعارض معلقًا ما لم يوجد له سند نظيف مستقل.
4. طي الحزمة الكاملة في مجال محدد، وفكها كبيانات، وإعادة بنائها من مدخلات مستقلة للتحقق.

تمتد الواجهة القائمة وتستعمل سجل سياساتها. لا يوجد سجل مبرهنات
ثانٍ أو اعتماد على تشغيل Mashru. لا يضيف العدد المطوي قرينة أو
ترخيصًا؛ تبقى هويته منفصلة عن رقم `Program` ورقم شجرة الجبر العودي.

مصادر مؤلفة يدويًا وتوقعاتها قبل كتابة الاختبارات ضد المحولين
الجديدين. لم يستخرج الـgold من دالة الإغلاق أو مصنف الإنتاج، ولم
يعدل للحصول على نجاح. هذا ترتيب تأليف مستقل موثق في السجل؛ لا
يدعي التقرير إيداعًا سابقًا لكل التنفيذ أو اختبارًا عربيًا محجوبًا.

يحفظ [سجل القبول](../evidence/mantuq_source_fold_v1/acceptance_verification.json)
الأوامر والسجلات الأولى وبصمات الشيفرة والاختبارات والفاحصين، ويميز
لقطات ما قبل إضافة فحوص CLI وأولوية السياسة واشتراط وجود المنفذات.
لا تجمع الإعادات اللاحقة مع هذا المقام باعتبارها اختبارات جديدة.

تستعمل الحالات الدلالية Lean الفعلي. فحص المهلة يراقب النداءات مع
تمريرها إلى المنفذات الحقيقية؛ المحاكاة المحدودة تخص إثبات عدم
استدعاء برنامج في المدخل المعيب أو في عملية الفك فقط. لم تستبدل
نتيجة دلالية مصطنعة بنتيجة Lean.

**ملاحظة تصنيف في العقد المحفوظ:** يدرج حقل `existing_owners`
الدالتين `Program.from_bytes` و`Program.from_number` ضمن مراجعه.
هما مرجع حسابي للاستعادة، وليسا استدعاءين تنفيذيين في هذه الوصلة.
بقي ملف القبول الأصلي وبصمته محفوظين؛ يحدد جدول المالكين في دليل
التشغيل الاستعمال التنفيذي الفعلي.

## الحالات الفاصلة

| تغير المعطيات | السلوك المرصود |
| --- | --- |
| المقدمات النظيفة والقاعدة المصدرية مكتملة | `SUPPORTED`، مع استنتاج مشروط |
| غياب شاهد نفي المانع | `UNKNOWN` |
| ثبوت المانع بدل نفيه | رفض طريق التطبيق، دون إثبات نفي الاستنتاج |
| وجود الشاهدين المتعارضين | `CONFLICT` مع حفظهما |
| اشتقاق مقدمة من أصل متعارض | `DEFER` دون تحويلها إلى واقعة نظيفة |
| إضافة أصل نظيف مستقل، ثم سحبه | دعم ثم عودة التعليق |
| تعارض خارج طريق المقدمات النظيفة | استمرار الدعم ضمن المصدر |
| دورة اشتقاق بلا أصل | بقاء النقص؛ لا يصنع الدور شاهدًا |
| تبديل المصدر أو السؤال أو النسخة أو الميزانية | رفض إعادة اعتماد الحزمة القديمة |
| تعديل الحكم وإعادة حساب SHA الصحيح | رفض المقابلة مع إعادة التنفيذ المستقلة |
| نفاد المورد أو غياب الفاحص | فشل تقني متميز؛ لا حزمة طي ناجحة |

شملت المراجعة الثانية
[24 تجربة مستقلة](../evidence/mantuq_source_fold_v1/independent_review/summary.json)
وسبعة تشغيلات CLI مع فحصين لبايتات المخرج وسلطته. لم تجد
[المراجعة](../evidence/mantuq_source_fold_v1/independent_review/final_review.json)
خللًا مانعًا في الملفات الستة المفحوصة، وظلت بصماتها متطابقة بين
القراءة والتجارب. هذه التجارب مقام آخر، ولا تضاف إلى 38 دالة unittest.

## المثال التنفيذي المحفوظ

أعيد تشغيل أوامر الواجهة على الملفات الموجودة في
`examples/mantuq_source_fold/`. نجحت خمسة أوامر:

| المخرج | الحالة |
| --- | --- |
| قراءة مثال السبب المشروط | `SUPPORTED` |
| طيه | `FOLDED_TRANSPORT` |
| فكه | `DECODED_UNVERIFIED` و`verified=false` |
| إعادة فحصه | `VERIFIED_REPLAY` و`verified=true` |
| قراءة مثال المخالفة ذي الضرورة الصريحة | `SUPPORTED` |

حُفظت الحزم كاملة والأوامر وبصمات الملفات في
[سجل المثال](../evidence/mantuq_source_fold_v1/example/summary.json).
في جميع النتائج بقي `world_truth_established=false`. الحزمة المطوية
تحتوي تفسير المصدر وحدوده، وليست شهادة بصحة المصدر في العالم.

## البناء والفحوص العامة

استُعملت أداة Lean المثبتة `4.34.1`، بعد مطابقة أرشيفها بالبصمة
المعلنة في `tools/bootstrap_lean.py`. اجتاز بناء المكتبة والمنفذات
الافتراضية إعادة فحص كاملة مسجلة بـ225 مهمة بناء، واجتاز بناء جميع
المنفذات الـ39 بـ264 مهمة. هذه أعداد مهام بناء، وليست أعداد مبرهنات
جديدة أو مقامات تغطية لغوية.

حُفظت محاولتان سابقتان كما لوحظتا: تعذر على Lake تحديد تثبيته
داخل البيئة المقيدة؛ وبعد تشغيل البناء في البيئة المأذونة عاد
برمز نجاح لكن ملف سجله المرئي كان جزئيًا. لم يعتمد التقرير ذلك
السجل الجزئي بوصفه سجلًا مكتملًا. تحفظ
[إعادة البناء](../evidence/mantuq_source_fold_v1/validation/formal_complete_replay.json)
خاتمة النجاح الكاملة وبصمتها، مع كتابة السجل دفعة واحدة بعد خروج
العملية. لا تُطمس الملاحظات السابقة لإظهار محاولة أولى مثالية.

طابقت ملفات التنفيذ المجمدة الـ99، وبقي `Makefile` وسير CI الرئيسي
وسجل المبرهنات مطابقًا لبايتات الأساس؛ راجع
[مطابقة التجمدات](../evidence/mantuq_source_fold_v1/validation/frozen_inputs.json).
شغلت البوابة الشاملة بـ`make check` مع ملاحق الفهرس والاستدلال
والحقيقة اللغوية والاستدلال المرخص، **وانتهت برمز 0** في
1569.863 ثانية محليًا. هذا زمن البوابة المحلية الموسعة مع المنفذات
الأصلية، ولا يقرر زمن أي وظيفة GitHub أو يغير مهلة العشرين دقيقة.

يميز هذا العد تخطي `setUpClass` من تخطي دالة اختبار: يسجله
`unittest` في قائمة التخطي، لكنه لا يدخل في `testsRun`. صححت
المطابقة النهائية عدد النجاح الأولي من 3047 إلى 3048 بعد عد سطور
النتائج الفعلية؛ حفظ [سجل التصحيح](../evidence/mantuq_source_fold_v1/validation/discovery_count_correction.json)
العدد السابق وطريقة التصحيح وبصمة السجل الأصلي دون تغييره.

التخطي في الاكتشاف العام لم يحوّل إلى نجاح. وقد جلبت البوابة
اللاحقة مصدر QAC المثبت وشغلت تقييماته القائمة؛ لم يعد تشغيل
الاكتشاف العام لإخفاء تخطيه الأول. كذلك لم تجمع إعادة اختبارات
المالكين أو الحالات العددية مع عدد الدوال المتميزة.

[ملخص التحقق](../evidence/mantuq_source_fold_v1/validation/verification_summary.json)
النتائج بالشيفرة الفعلية. لم يُبدل أصل أو gold أو حد قبول للحصول
على النجاح. تبقى بوابات GitHub على رأس النشر شرط الدمج؛ لا يستعار
نجاحها من هذا التشغيل المحلي أو من PR آخر.

اكتملت لاحقًا جميع بوابات رأس التنفيذ الأول
`310dfba60f9be268b4f410627ad0978907976b78`: نجحت 21 وظيفة فحص

وهذا يختلف عن اكتشاف Python العام على عمال لا تتوافر عندهم جميع

## الاستمرار والتوافق

أضيف المسار إلى عائلة `mantuq-mafhum` الموجودة في سجل إعادة
الاستعمال، وإلى المدخل القائم وتعليمات `AGENTS.md` ووثائق الأساس
والاستدلال. صار هدف `mantuq-inference` يشترط الفحوص الأصلية الجديدة
عبر `mantuq-source-fold`. غياب أي فاحص مع علم البوابة الإلزامي يفشل
تحميل الاختبارات بدل إعلان نجاح مع التخطي. تستدعي بوابة
`catalog-proof-links` القائمة الهدف نفسه؛ بقيت مهلة العشرين دقيقة.

نجحت المقابلة النصية للملفات المشتركة مع رأس PR65 عند
`1fe09dbceda92a5d6cc2fbee5c3f3ea42b8bf688`. ونقل مقطع التوثيق داخل
القسم التاسع حافظ على دراسة SLGE غير المدمجة في المستودع الأصلي
دون تصادم إضافتين عند نهاية الملف. يحفظ
[سجل التوافق](../evidence/mantuq_source_fold_v1/pr65_compatibility_review.json)
البصمات وحدود الفحص. التوافق النصي ليس نجاح تشغيل تكاملي ولا إذن
دمج يتجاوز بوابات الرأس المنشور.

## ما بقي مفتوحًا

النتيجة مفحوصة بالنسبة إلى قراءة أرضية مضبوطة واحدة، وخطة تعيين
أدوار معلنة، وسياسة مثبتة، ومقدمات مصدرية. يبقى استخراج الأدوار
تلقائيًا من العربية، واكتمال قراءاتها، وأصالة الخبر، واعتماد القاعدة
وصحة انطباقها في الخارج، وسلطة الفعل، وبرهان تنقيح المحول، وبرهانا
القناع والاكتمال ضمن نحو ومعجم معينين، التزامات مستقلة. لم ينفذ
تدريب شبكة أو تجربة تعميم مفاهيمي في هذه الدفعة.

المكسب الحالي للتعلم اللاحق محدد: أصبح للانتقال المقترح سجل قابل
لإعادة البناء يضم المصدر ومقدماته والقاعدة وبقايا الحكم وأثر سحب
الشاهد. يمكن استعمال هذا السجل لبناء أمثلة تعلم من اشتقاقات معلومة
السند، مع بقاء الاقتراح المتعلم خاضعًا للفاحص نفسه.
