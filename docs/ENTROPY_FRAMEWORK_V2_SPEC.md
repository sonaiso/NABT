# مواصفة إطار المتابعة v2

**الحالة: عقد قبل التنفيذ وتجميد الذهب.** يضاف هذا العقد إلى دفعة المصدر
الأولى؛ لا يعني وجوده أن سجل v2 أو فاحصه منفذان. يعالج الفصل بين تسليم
العمل، وقياس نطاق محدد، وجاهزية مراجعة قبول البوابة. تبقى قوانين NABT
ومجموعاته ونتائجه التاريخية مستقلة عن بيانات المتابعة.

## الهوية وحد السلطة

| الواجهة | الهوية |
|---|---|
| السجل | `nabt.entropy-framework.registry.v2` |
| إصدار وصف الإطار | `schema_version: "0.2.0"` |
| التحقق | `nabt.entropy-framework.validation.v2` |
| التقرير | `nabt.entropy-framework.report.v2` |
| عد المرشحين | يبقى `nabt.candidate-ledger.v1` دون تغيير |

السجل يصف الأدلة ولا يوثق صحتها. تبقى مخرجات التحقق
`authority=METADATA_CONSISTENCY_ONLY`، ومخرجات التقرير
`authority=DECLARED_RECORDS_ONLY`، وفي كليهما `semantic_authority=NONE`
و`evidence_verified=false`. يبقى `release_admission=NOT_EVALUATED`.
لا تنتج البصمة أو حالة PASS أو `READY_FOR_REVIEW` قبولًا لغويًا أو اعتماد
إصدار. لا يستورد هذا الجزء محرك الاستدلال ولا يشغل المقيّم المشار إليه.

تظل عقود v1 للمعرفات، والأدوار المختلفة للمسؤول والمراجع، والمقامات،
والبيانات المجمدة، وهوية التشغيل، وقراءة JSON وميزانيتها نافذة ما لم
يستبدلها بند صريح أدناه. لا يحول الفاحص v1 إلى v2 ضمنيًا؛ ترحيله تغيير
مسجل ومراجع. لا يغير هذا العقد سلطة عد السجل `COUNTED_SUPPLIED_LEDGER`.

## قياس البوابة وجاهزية مراجعتها

يحذف v2 الحقول التشغيلية الملتبسة `gate.status` و`gate.evidence_ids`
و`gate.baseline`، ويستبدلها بكائن `measurement` ذي الحقول التالية فقط:

```json
{
  "state": "MEASURED",
  "reported_outcome": "PASS",
  "evidence_ids": ["productive-clause-v1.exposed-review1.c694a5a"],
  "reason": null
}
```

| `state` | `reported_outcome` | الأدلة والسبب |
|---|---|---|
| `NOT_MEASURED` | `null` | قائمة فارغة؛ `reason` فارغ أو نص توضيحي |
| `MEASURED` | `PASS` أو `FAIL` | قائمة غير فارغة؛ نتيجة معلنة للنطاق نفسه |
| `STALE` | `PASS` أو `FAIL` | مراجع نتيجة سابقة محفوظة، وسبب تقادم غير فارغ |
| `NOT_APPLICABLE` | `null` | قائمة فارغة وسبب غير فارغ؛ لا يعفي اعتمادًا آخر |

يعني «فارغ» لحقل `reason` القيمة `null`؛ النص إن وجد غير خالٍ. يستبدل
الحقل الأعلى `gate_states` بـ `measurement_states` مطابقًا هذه الحالات.
كل مرجع معروف وفريد ومربوط بمعرف البوابة ونطاقها. في `MEASURED` يلزم
تجميد المجموعة وتطابق إصدارها وبصمتها مع كل تشغيل مشار إليه. PASS يتطلب
أن تصرح كل السجلات المختارة بالنجاح، وأن تكون فحوصها المطلوبة غير فارغة
بلا فشل أو تجاوز أو فحص مفقود. FAIL يتطلب سجلًا مختارًا يصرح بالفشل.
لا يشترط نجاح اعتماد البوابة لتسجيل قياسها. في `STALE` تبقى هوية التشغيل
القديمة؛ قد تختلف عن المجموعة الحالية، ولا تستعمل لقبول الحاضر.

يعيد التقرير `measurement` مستقلة عن كائن `admission` المحسوب؛ الأخير
ليس مدخلًا في السجل:

```json
{
  "readiness": "BLOCKED_DEPENDENCIES",
  "blockers": ["G0", "GM"],
  "decision": "NOT_EVALUATED",
  "evidence_verified": false
}
```

يحسب التقرير الجاهزية بترتيب اعتماد البوابات: إذا لم يكن القياس
`MEASURED/PASS` فالحالة `BLOCKED_MEASUREMENT`. وإلا، إذا لم تكن جاهزية
كل اعتماد مباشر `READY_FOR_REVIEW` فالحالة `BLOCKED_DEPENDENCIES`.
وفي غير ذلك تكون `READY_FOR_REVIEW`. يعرض `blockers` معرفات الاعتمادات
المباشرة غير الجاهزة بترتيب `depends_on`، حتى لو تعطل قياس البوابة نفسها؛
يفسر حقل القياس سبب التعطل الذاتي. `decision` دائمًا `NOT_EVALUATED`.
هذه جاهزية بيانات للمراجعة وليست قبول الاعتمادات أو توثيقها.

لا يقبل السجل حقل `admission` أو حقول سلطة مثل `evidence_verified`
و`semantic_authority` داخل البوابة أو القياس أو سجل الدليل. لا يرفع أي
حقل وصفي إضافي سلطة التقرير. تبقى حالات القدرة الجزئية
`PLANNED/SOURCES_FROZEN/IMPLEMENTED_AWAITING_EVALUATION/EVALUATED`؛
`EVALUATED` تعني وجود قياس مصرح به، وقد يكون فاشلًا أو متقادمًا.
يربط التقرير القدرة بقياس بوابتها وجاهزيتها، ولا ينشئ قبولًا موازيا.

## نطاق التسليم واعتمادات المهام

تضاف لكل مهمة `scope` غير فارغة و`parent_task_id` إما معرف مهمة معروفة
أو `null`. تبقى `depends_on` للاعتمادات اللازمة لتنفيذ تسليمها؛ علاقة
الأبوة تجميع تنظيمي منفصل ولا تشترط إكمال الأب قبل تسليم الابن.
يفحص كل من رسم الاعتماد وشجرة الأبوة ضد الدورات والمراجع المفقودة.
تحذف `task.gate_status`؛ تعرض البوابات المرتبطة حالاتها في التقرير نفسه.

تبقى حالات العمل `PLANNED/READY/IN_PROGRESS/IN_REVIEW/DELIVERED/BLOCKED`.
تتطلب `READY` و`DELIVERED` تسليم كل الاعتمادات الصريحة. يتطلب تسليم أب
أيضًا تسليم أبنائه المسجلين، لكنه لا يستنتج تلقائيًا من تسليمهم: قد تبقى
التزامات في نطاق الأب. `DELIVERED` إعلان تسليم في النطاق المحدد، لا
توثيق للدليل ولا نجاح للبوابة. يعرض التقرير نطاق كل مهمة وأباها وأبناءها
واعتماداتها غير المسلمة.

توحد مراجع نتائج المهام في `evidence_ids`؛ يرحل `scoped_evidence_ids`
إليها دون تغيير سجلات الأدلة. يجب أن تتبع الأدلة بوابة في `task.gates`؛
إحالة مهمة إلى نتيجة واسعة لا تعني أنها نفذت كل فحوصها. تسليم مواصفة أو
كود لا يحتاج اختلاق سجل قياس؛ يحفظ مرجع التسليم وشرحه منفصلين.

| المهمة | التوفيق المطلوب في v2 |
|---|---|
| T02، T04 | أبوان `IN_PROGRESS`؛ تمديد الشهادة وبروتوكولات المشروع غير مكتملين |
| T02-PCV1 | ابن T02، تسليم شهادة الجزء الفعلي؛ يعتمد T01؛ `DELIVERED` |

| T05 | تسليم عد السجل المقدم؛ يعتمد T03 فقط، لأن ربط المصدر غير مصدق بهذه الأداة |

الحالات الأخيرة تحدد بحسب المنجز عند تحديث السجل، لا بمجرد هذه المواصفة.

تصحيح اعتماد T10: تقييم لقطة المصدر الثابتة لم ينفذ سحب الشواهد؛ لا

## ترحيل محافظ من v1

مصدر الترحيل هو البايتات الأصلية، دون إعادة تنسيق قبل حساب البصمة:

- commit: `c2c072e17802b62c13109cee7c087b7b58895a1a`.
- path: `tools/entropy_framework/registry.json`.
- schema: `nabt.entropy-framework.registry.v1`.
- SHA-256: `09ad43d5602e5f00fa3ea50b8bae89dbea2aa064b77a604dea1a80a910a8c8bb`.
- Git blob: `99a6b2c2b82ad316eee5ab3a5222763dee547a17`.

يسجل v2 كائن `migration` يحوي `source_schema/source_commit/source_path/`
`source_sha256` بهذه القيم، و`changes` قائمة غير فارغة من
`{id, affected_ids, reason}`؛ المعرفات فريدة والأسباب غير فارغة.
هذا نسب تغيير تنظيمي، لا ادعاء أن الفاحص أعاد قراءة نسخة Git أو وثقها.

ترحل الحالات القديمة إلى `measurement`: NOT_MEASURED كما هي، PASS/FAIL
إلى MEASURED بالنتيجة نفسها، وSTALE/NOT_APPLICABLE وفق شروطهما أعلاه.
الاستثناء المفسر G1: ينقل إليه مرجع review1 الموجود من قدرة PCV1، فيصبح
`MEASURED/PASS` وجاهزيته `BLOCKED_DEPENDENCIES` مع G0 وGM. لا يعاد تشغيل
200 ولا تبدل نتيجة أو هوية أو مرحلة `exposed` بهذا الترحيل. تبقى سجلات
الأدلة التاريخية ومحتويات `baseline` الحالية كما هي، بما فيها أساس
`b7442580e7e681a68a85f40bc247be8ee286e7e3`. c2c072e أساس الترحيل لا بديل
عن أساس القياس. تحذف الحالات المكررة بعد تسجيل التصحيح؛ لا تنتج قراءة
v2 القديمة عبارة مضللة بأن مصفوفة 200 غير مقاسة.

## جزء دورة الحياة وحدود هذه الدفعة

يسجل `evidence-lifecycle-v1` قدرة مرتبطة بالبوابة الموجودة **G4**، دون
إنشاء بوابة موازية. كان عقد G4 مقترحًا غير مقاس؛ لذلك يوثق `migration`
انتقاله إلى النطاق المحدد `nabt.evidence-lifecycle.v1` في
`docs/EVIDENCE_LIFECYCLE_V1_SPEC.md`، وتبقى تبعيته لـG0. بعد تجميد الذهب
فقط تصبح مجموعته `frozen` بهويتها وبصمتها وcommit الذهب الفعلي؛ لا تستعمل
أرقامًا بديلة أو هوية مستقبلية. عائلات البروتوكول خمس، كل منها ثمانية:
`withdrawal/lineage/conflict/qualified_key/revision_and_absence`.
يحفظ الترحيل النطاق والتقسيم المقترحين السابقين، وتعليل استبدالهما؛ لا
يوجد قياس G4 سابق تعاد كتابة معناه. ينشر مقام السيناريوهات ومقام
الخطوات منفصلين، وتبقى المجموعة غير مقاسة حتى وجود تشغيل محفوظ.

| متطلب G4 الحالي | ما يقاس في المجموعة المجمدة |
|---|---|
| مطابقة الأربعين مع الامتناع المشروع | نجاح جميع خطوات كل سيناريو، بما فيها التعليق والاستنفاد |
| التعارض المشروط | قطبيتان متقابلتان لمفتاح مؤهل مطابق؛ اختلاف الزمن أو الوحدة أو المفتاح لا يولد نفيًا |
| سحب السند ومراجعة التوابع | تعليق أو إعادة تسويغ بحسب الأصول المعلنة النشطة؛ حفظ الإيصالات التاريخية وفصلها عن الحالية |
| انتظار G2/G3 للدمج النهائي | قيد باقٍ؛ اختبارات وصل الجزء الفعلي منفصلة، ولا تعد إنجازًا للدمج الدلالي العام |

إذا نجح التشغيل يسجل G4 `MEASURED/PASS` في هذا العقد المحدد. عند بقاء
G0 غير جاهزة تكون جاهزيته `BLOCKED_DEPENDENCIES`، ويبقى قراره
`NOT_EVALUATED`. تفسر النتائج المقيسة كما هي، ولا توصف مجموعة الأربعين
بعد تشغيلها بأنها غير منشأة أو غير مقاسة.

نجاح الجزء يصف أربعين سيناريو مؤلفًا وشروطها المصرح بها. لا يثبت صدق
العالم أو استقلال مصادره الفعلي أو اكتمال G2/G3 أو قبول G4. تظل استعادة Ω العامة،
وتوسعة الزمن إلى فترات، وتحويل الوحدات، وتعارض المحمول أحادي القيمة،
والإحالة الخارجية أهدافًا مفتوحة. إعداد T11 لا يصنع 120 حالة عرفية.

## فحوص قبول تنفيذ هذا العقد

يلزم اختبار مستقل يقبل تسجيل قياس PASS مع اعتماد غير جاهز ويعرض الفصل،
ويرفض تبديل نطاق الدليل أو المجموعة، وتسليم مهمة قبل اعتمادها، ودورات
الأبوة، وادعاء توثيق الدليل داخل السجل. يثبت مثال مصطنع متسق أنه لا
يحصل على سلطة أو قبول حتى عند `READY_FOR_REVIEW`. تختبر مهمة ابن مسلمة
مع أب غير مكتمل، وتسجيل قياس G4 مع بقاء قبولها غير مقيم وG2/G3 غير
مقاسَتين، وحفظ baseline وسجل PCV1 التاريخيين دون تعديل. لا يبدأ تنفيذ الفاحص أو تعديل
السجل أو اختبارات التنفيذ قبل تثبيت الذهب المستقل لهذه الدفعة.
