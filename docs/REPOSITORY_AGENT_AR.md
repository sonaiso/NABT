# وكيل إدارة مهام NABT

## عقد القبول المثبت قبل التنفيذ

الوكيل مدير تنفيذ محلي داخل المستودع. يتلقى مهمة ونطاق ملفات ومعايير قبول
ومقترح تعديل محددًا، ويقرأ سجل إعادة الاستخدام الحالي قبل التخطيط. يستعمل
بوابات المشروع القائمة، ولا يضيف محرك استدلال أو سجل مبرهنات أو قانون قبول
لغوي. الاقتراح يمكن أن يأتي من إنسان أو نموذج؛ لا تمنحه درجة النموذج سلطة
اعتماد، ولا يفترض هذا الإصدار اشتراك API أو عملية تعمل باستمرار.

الفجوة التي يغلقها: موزع `reuse_run` ينفذ مدخلًا موجودًا، وخريطة `reuse`
تعرض أصحابه وحدوده؛ لا يديران مهمة تعديل مثبتة النسخة، ولا يعزلان التعديل
عن عمل المستخدم، ولا يجمعان خطة الفحوص وسجل نتيجتها في دورة واحدة.

شروط قبول هذه الوصلة:

1. المهمة مثبتة إلى التزام Git كامل، وبها الهدف، والمسارات المأذونة بالضبط،
   ومعايير قبول نصية. لا تتحول المعايير النصية إلى دعوى أنها فُحصت آليًا.
2. المقترح بيانات ذات مخطط مغلق: مسار، وبصمة المحتوى السابق أو عدم وجوده،
   ومحتوى UTF-8 جديد أو حذف. لا يحتوي أوامر أو أعلام نجاح أو برنامج فحوص.
3. يرفض اختلاف الأساس أو المحتوى السابق، والمسارات المتسللة والروابط،
   وتعديل سياسة الوكيل أو الشواهد التاريخية أو الفحوص القائمة عبر هذا المسار.
4. يجرب التعديلات داخل Git worktree منفصل، ولا يبدل ملفات المستخدم أو فرعه.
   يستخرج التأثير والمراجع من سجل إعادة الاستخدام الموجود. غير المعين يبقى
   غير معين، ولا يختار الوكيل عائلة لمجرد تشابه الاسم.
5. يختار فحوصًا من سياسة شيفرة ثابتة؛ لا يمكن للمهمة حذف الفحوص اللازمة.
   فحوص Python/Lean وإعادة الاستخدام تحتفظ بمعانيها وحدودها الأصلية.
6. يحفظ المدخلات والخطة والتحولات والسجلات وهوية الشجرة. يتوقف عند الإخفاق
   أو غياب أداة أو مهلة أو تغير ملفات أثناء الفحص؛ لا يقرر الجاهزية لنسخة
   مختلفة عن النسخة المفحوصة. تحتفظ المحاولة الفاشلة بأدلتها.
7. النجاح ينتج مرشح تغيير محليًا قابلًا للمراجعة، وليس تصريح إصدار أو دمج
   أو نشر أو شهادة اكتمال العربية. التحقق الجديد يعيد الفحوص من المدخلات
   المستقلة؛ قراءة ملف حالة سابق وحدها ليست إعادة تحقق.

هذه إدارة مهام وشيفرة موثوقة من صاحب المستودع. عزل worktree يحفظ تنظيم
الملفات، وليس sandbox أمنيًا لتشغيل برنامج عدائي. الفحوص تنفذ شيفرة المرشح
بصلاحيات العملية؛ يستعمل البرنامج مهلات وحدود سجلات وبيئة محدودة، لكنه لا
يدعي عزل الشبكة أو نظام الملفات. لا يشغل النموذج تلقائيًا ولا ينشئ إصلاحًا
من وصف حر وحده؛ يطبق المقترح المحدد ثم يقرر المسار اللاحق من نتائج الفحص.

## الواجهة والاستعمال

توجد الشيفرة تحت `tools/repo_agent/`: `policy.py` لحدود المدخلات والفحوص،
و`repository.py` لهوية Git والتعديل المعزول، و`manager.py` لدورة التنفيذ،
و`state.py` للسجل والحالة. نقطة الدخول `python -m tools.repo_agent` مسجلة
كذلك في موزع إعادة الاستخدام القائم باسم `repo-agent`. هي أداة إدارة؛
لا تُنسب إلى عائلة مبرهنات على أنها مستهلك برهاني جديد.

```sh
python -m tools.repo_agent inspect
python -m tools.repo_agent plan --task task.json --proposal proposal.json
python -m tools.repo_agent run --task task.json --proposal proposal.json \
  --output-dir artifacts/local/repo-agent/my-task
python -m tools.repo_agent status --run-dir artifacts/local/repo-agent/my-task
python -m tools.repo_agent verify --task task.json --proposal proposal.json \
  --run-dir artifacts/local/repo-agent/my-task \
  --output-dir artifacts/local/repo-agent/my-task-replay
```

للتجربة على NABT نفسه من checkout نظيف:

```sh
python examples/repo_agent/demo.py --output-dir artifacts/local/repo-agent/demo
python examples/repo_agent/demo.py --counterexample \
  --output-dir artifacts/local/repo-agent/counterexample
```

ينشئ المثال مدخلين مثبتين إلى HEAD، ويضيف وثيقة داخل worktree المرشح فقط،
ويشغل بوابات إعادة الاستخدام الفعلية، ثم يعيد التجربة في worktree آخر.
يفحص أن checkout الأصلي بقي مطابقًا. يحفظ `task.json` و`proposal.json`
مثالًا كاملًا للمخطط يمكن تكييفه لمهمة حقيقية.
أما المثال المضاد فيغيّر عمدًا إزاحة الترميز في `codec.py` داخل المرشح؛
يلزم أن ترفضه اختبارات صاحب الترميز الأصلية قبل الوصول إلى الجاهزية،
وأن يبقى الملف الأصلي دون تغيير. ليست هذه تجربة تعلم إصلاح من نموذج.

المهمة تحمل `schema/id/base_commit/goal/allowed_paths/acceptance`.
والمقترح يحمل `schema/base_commit/rationale/changes`؛ كل تغيير يحمل
`path/before_sha256/content`. تعني بصمة `null` أن الملف جديد، ويعني المحتوى
`null` حذف ملف موجود. لا تُستخدم glob في نطاق المسارات. يجب أن يطابق الأساس
HEAD كاملًا وأن تكون النسخة الأصلية نظيفة؛ تبقى الملفات المحلية المتجاهلة
بحسب Git خارج التغيير. تعاد قراءة المحتويات السابقة قبل تطبيق المقترح.

## القرار والشواهد

يعين الوكيل المالك بالمراجع الفعلية في `reuse` ويحفظ نطاقه والتزاماته.
التوثيق النصي تحت `docs/` يحتاج فحص الفرق وإعادة الاستخدام. تغيير الشيفرة
أو الأمثلة يحتاج كذلك الاختبارات العامة وسلامة الأصول ومطابقة النموذج
المتعلم. تُبنى المنافذ الأصلية المشار إليها للعائلات المتأثرة قبل اختبارات
أصحابها التي تُكتشف من السجل، ثم الاختبارات العامة. تغييرات سلسلة التحصيل
والاستدلال والجملة والمراجعة وحفظ المعنى تستعمل كذلك وصفة
`meaning-preservation-conformance` القائمة، بشروطها الأصلية وإلزام حضور
المنافذ؛ وجود منفذ العائلة وحده لا يكفي لتغطية سلسلة المحول.
كل تغيير تحت `src/nabt/` أو `formal/`، وكذلك الشيفرة غير المعينة إلى مالك،
يضيف `formal` و`conformance` و`axioms` بصرف النظر عن وجود مالك في السجل.
فشل تحديث مرجع البرهان يبقى إخفاقًا؛ لا يعيد
الوكيل كتابة لقطة تاريخية كي تمر البوابة. يستعمل `lake` من PATH، ويلزم
تجهيزه بالأداة المثبتة في المستودع قبل مهام Lean.

يُنتج النجاح `READY_FOR_REVIEW` مع `candidate_commit` و`candidate_tree`
ومرجع محلي تحت `refs/nabt-agent/`. لا يحرّك الفرع الحالي ولا ينشر إلى GitHub.
يمكن فحص المرشح بأوامر Git المعتادة باستخدام معرف الالتزام المسجل.
تظل معايير المهمة النصية `NOT_AUTOMATICALLY_ASSESSED` حتى المراجعة المناسبة؛
نجاح الفحوص وحده لا يثبت أن كل هدف لغوي في وصف المهمة قد تحقق.

تظهر `CHECKS_FAILED` مع السبب الأصلي: إخفاق، أو أداة غير متاحة، أو مهلة،
أو حد مخرجات. ويظهر `BLOCKED` عند انحراف الشجرة أو تغير الأساس أو خطأ
تنفيذي؛ وتُحفظ المقاطعة كـ`INTERRUPTED` متى أمكن. فشل ما قبل إنشاء السجل
يعيد خطأ المدخل مباشرة. التوقف القسري للعملية قد يترك آخر حالة غير نهائية؛
لا يُستأنف من نتيجة جزئية بوصفها نجاحًا، بل يبدأ تشغيل جديد مثبت المدخلات.

`status` يعرض سجلًا دون إعادة تحقق. `verify` يحتاج الطلب والمقترح مستقلين،
ويفحص هوية السياسة والخطة والمرشح وسجلات الفحوص وتتابع الأحداث، ثم ينفذ
الفحوص من جديد. السجل محلي وغير موقع؛ سلسلة البصمات تكشف عدم الاتساق
ولا تثبت أصالة تاريخ أمام من يستطيع إعادة كتابة كل الملفات. تبقى
`historical_authenticity=NOT_ESTABLISHED` حتى بعد إعادة التنفيذ الناجحة.

## حدود الإصدار

النظام موجه إلى Linux/POSIX مع Git وPython 3.11 فأحدث. يحد المقترح بـ24 ملفًا،
و256 KiB لكل محتوى، و1 MiB للمدخل؛ ولكل فحص مهلة معلنة وسجلات محدودة.
تشمل الميزانية الملف الأصلي أيضًا، ويُحد مجموع الأصل والبديل بـ1 MiB؛
لا يصدر نجاح لرقعة تتجاوز حد إعادة فحصها البالغ 2 MiB.
تُحظر التغييرات الآلية في سياسة الوكيل وسجل إعادة الاستخدام والفاحصين
المحميين والشواهد التاريخية وبيانات القانون المولدة والاختبارات القائمة؛
وتُشتق حماية الفاحصين من جميع `checker_paths` المحلولة في الأساس المثبت،
وتشمل ملفات وصفات Make؛ لا تقتصر الحماية على بادئة اسم الفاحص.
يمكن إضافة اختبار جديد. تغيير تلك الأصول يمر بمسار تطوير ومراجعة خارجي
كما تمر به إضافة هذا الوكيل نفسه، ولا ينتج إذنًا من مقترحه.

تبقى worktrees والمرشحات والسجلات بعد المحاولة للمراجعة. إدارة الاحتفاظ
والتنظيف عمل صريح لاحق. لا توجد خدمة خلفية أو حلقة إصلاح غير محدودة أو
اتصال نموذج مفترض. يمكن لمولد مقترحات لاحق إنتاج المخطط نفسه دون منحه
تغيير السياسة أو حذف الفحوص اللازمة.
