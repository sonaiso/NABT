# تطبيق واقعة جديدة ومراجعة الحكم

القانون: `nabt.case-application.v1`؛ المجال: `warehouse-transfer.v1`.
الأصل المفحوص: `2de43d034b8477f9d8bebded399034fb1af973c3`.

## عقد القبول المثبت قبل التنفيذ

يعالج التطبيق استيفاء طلب نقل صندوق لشروط سياسة تشغيلية مؤلفة ومعلنة.
ليست السياسة لائحة سلامة معتمدة، ولا حكمًا شرعيًا، ولا إذنًا بتحريك معدات.
المدخل نصوص عربية مضبوطة؛ لا يدعي التطبيق قراءة العربية الحرة أو القياس
من جهاز. حكمه نسبي إلى هذه النصوص وإلى السياسة بنسختها.

يعيّن الطلب هوية الحالة والصندوق والناقل والمنشأ والوجهة والزمن. هذا تعيين
للمطلوب فحصه، لا شهادة على وجود هذه العلاقات. تحتاج كل علاقة إلى شاهد
في النص. الفحص والسلامة والتدريب والحجز علاقات محلية للحالة مع حاملها؛
لا تنتقل سلامة صندوق في حالة سابقة إلى حالة أخرى لمجرد ثبات اسم الصندوق.
الزمن والمكان اسمان صريحان في هذا المجال، لا قياس مدة أو مسافة.

السياسة: لا يستنتج استيفاء الطلب إلا مع إثبات المنقول والناقل والمنشأ
والوجهة والزمن وجنس الصندوق وفحصه وسلامته وتدريب الناقل ونفي الحجز صراحة.
تبديل اللون لا يؤثر. تعارض الحجز ونفيه يبقي التعارض؛ سحب نفي الحجز لا
ينشئ الحجز. معارضة شرط تمنع تطبيق هذه السياسة ولا تثبت نفي النتيجة عمومًا.

1. الحالة الإيجابية تجمع شواهد الشروط مع المصدر وموضع UTF-8.
2. سحب اللون أو تغيير قيمته يحفظ الحكم؛ يبقى اختلاف السجل ظاهرًا.
3. سحب شاهد لازم يجعل الحكم غير محسوم؛ إعادته تعيد الفحص.
4. ظهور الحجز مع نفيه يوقف القبول ويحفظ الشاهدين.
5. الحجز وحده يعارض شرط السياسة، دون ادعاء برهان نفي النتيجة.
6. تغيير الناقل أو الصندوق أو الزمن أو المكان يحتاج شواهد مطابقة جديدة.
7. عكس طرفي علاقة أو نقل الفحص من حالة أخرى لا يفي بالمقدمة.
8. الشاهد البديل المستقل يبقى بعد سحب الأول؛ النسخة التابعة لا تستقل عنه.
9. سحب السياسة نفسها يحجب التطبيق؛ لا يعاد إدخالها أثناء إعادة الفحص.
10. لا يقبل العميل حقن قاعدة أو نتيجة أو مسار مدقق أو رتبة صدق.
11. كل نتيجة خارجية تمر ببوابة NABT ويعاد تشغيلها مع الطلب المستقل.
12. غياب مدقق أو نفاد الموارد يحفظ عدم اكتمال المعالجة؛ لا يصبح نجاحًا.

## تحليل المسار الموجود وموضع الإضافة

قراءة الشيفرة وتجربة فعلية سبقت الإضافة: `source_learning_connection.evaluate`
وصل بالفعل قارئ النص و`SemanticKernel` واستنفاد الدعم ومراجعة المصادر
بـ`VerifiedReading` و`EvidenceLifecycleV1`. أعادت تجربة أولى سحب اللون
دون تغير الحكم، وحجبت الاستدلال عند تعارض المقدمة وسحب الشاهد.
إذن لم تكن الحاجة إنشاء محرك استدلال أو دورة حياة جديدة.

الفجوة المحددة هي غياب تطبيق خارجي ثابت يعيّن سياسة حالة مع علاقاتها،
ويشرح التغيرات، ويميز معارضة شرط عن نفي الحكم. يضيف `application.case`
هذا التنسيق فوق المالك الموجود، ويستخدم `mantuq_inference.source_bound`
بسياسة المطابقة `matching` وشروطها، دون تسميتها سببية فيزيائية.

تبقى القراءة الأصلية ومواضعها، والتأريض وخريطته، وشواهد الدعم النظيفة
والمتعارضة، وجميع تقارير المالكين محفوظة. قائمة المتطلبات مشتقة من سياسة
التطبيق المعلنة؛ ليست سجل مبرهنات جديدًا. فهرس Lean الحالي هو المرجع.

## حدود البرهان والمعرفة

الفواحِص الأصلية تتحقق من النظرية الأرضية ودورة حياة الأدلة. تركيب المحولات
وتعيين السياسة ومعنى مفردات المجال يخضع لاختبارات مستقلة؛ لا تدعي هذه
الدفعة برهان تنقيح عام لمحولات Python. لا تصبح تسميات المفاهيم أو البصمات
إثباتًا لصدق الوقائع. قوة النتيجة `SOURCE_RELATIVE_CONDITIONAL` فقط، مع
حقول مستقلة للمطابقة المصدرية وفحص الاستدلال وتحقيق الحالة داخل السجل.

لا يضاف تدريب عصبي في هذا التطبيق. لا تتطلب المطابقة ذاكرة أمثلة متشابهة؛
تقبل هويات جديدة داخل النطاق. يحتفظ السجل بالوقائع والشواهد اللازمة
لإعادة الفحص، وبالاختلاف بين التاريخ الماضي والحالة النهائية.

## التشغيل من الشيفرة إلى المعالجة

من جذر المستودع، بعد بناء الفواحِص بأداة Lean المثبتة:

```sh
make io-gateway-build LAKE=/absolute/path/to/lake
cd formal && /absolute/path/to/lake build evidenceLifecycleV1
cd ..
python examples/case_application_client.py
```

يحفظ العميل الطلب مستقلًا، ويشغّل `gateway run` ثم `gateway verify`، ويعرض
خلاصة عربية بعد القبول. النتائج والطلب والشهادة الكاملة محفوظة تحت
`artifacts/local/case-application-client/`. رمز الخروج ٣ يعني أن إعادة
النقل نجحت لكن سلسلة التطبيق لم تكتمل؛ لا يُعد قبول البوابة حكمًا موجبًا.

المسار المباشر نفسه:

```sh
PYTHONPATH=src:. python -m tools.grammar_catalog gateway run \
  --request examples/io_gateway/case_application.json --output /tmp/case-receipt.json
PYTHONPATH=src:. python -m tools.grammar_catalog gateway verify \
  --request examples/io_gateway/case_application.json --receipt /tmp/case-receipt.json
```

تتضمن الحالة المودعة الهوية `نقل731` والصندوق `صندوق731` والناقل `سالم`.
علاقات `فحص/سلامة/تدريب/حجز` محلية للحالة؛ مثل `نقل731 سلامة صندوق731.`.
المعجم التشغيلي والسياسة بنسختها في
`tools/grammar_catalog/data/warehouse_transfer_v1.json`، وليس في بيانات العميل.

| الخطوة | تعديل الشاهد | قرار تطبيق السياسة المتوقع |
|---|---|---|
| ٠ | الشواهد الأصلية | `SUPPORTED` |
| ١ | سحب اللون | `SUPPORTED` |
| ٢ | ورود حجز يعارض نفيه | `CONFLICT` |
| ٣ | سحب نفي الحجز | `NOT_APPLICABLE` |
| ٤ | سحب الحجز أيضًا | `UNKNOWN` |
| ٥ | استعادة نفي الحجز | `SUPPORTED` |
| ٦ | سحب الفحص والسلامة | `UNKNOWN` |
| ٧ | استعادة الفحص والسلامة | `SUPPORTED` |
| ٨ | سحب السياسة | `UNKNOWN` |
| ٩ | استعادة السياسة | `SUPPORTED` |

`source_ledger` يحفظ كل خبر وموضعه وعلاقته الموقعة. تربط `requirements`
الشروط بمؤشرات شواهدها ومعارضاتها. يحمل `owner_result` القراءة والدعم
البديل والمراجعة كاملًا، و`qualified_replay` فحص تطبيق الشروط. الحكم الجاري
في `current_decision` لا يصدر عند عدم اكتمال السلسلة. السحب لا يحذف التاريخ.

بوابة القبول المطلوبة: `make case-application LAKE=/absolute/path/to/lake`.
تدخل في `make check` وفي CI الحالي للبوابة. تتضمن اختبارات مستقلة بحذف كل
واحد من الشروط العشرة، وتبديل الهويات، وعكس العلاقة، وتغيير السياق، ونفي
السلامة، وتعارض الحجز، والنسخة التابعة، والتلاعب بالشهادة، وعدم توافر المدقق.
