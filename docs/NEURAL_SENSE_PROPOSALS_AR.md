# اقتراح المعاني من الشواهد مع بقاء القبول للعقد الموجود

يضيف هذا التغيير وضعًا اختياريًا إلى `tools/propose_lexical_evidence.py`:
نص عربي وجذر معجمي مصرح به → ترتيب عصبي لكل معاني الجذر المثبتة →
إيصال `tools.lexical_testimony.assess` القائم كاملًا. تعاد قراءة المصادر
ومقارنة فهرس Lean وتنفيذ `lexicalDenotation` عند كل استدعاء.

الموضع الناقص الذي يعالجه هو ترتيب **معاني** الفهرس من وصف نصي؛ كان
مقترح الأدلة القائم يرتب مداخل مقاييس اللغة. يحتفظ الوضع السابق بسلوكه.
أُعيد استعمال ترميز الكلمات والمقاطع الحرفية في `lexical_training`، وفُصل
فقط إلى وحدة مشتركة لا تتطلب Torch. بقيت أدوات الصرف وقطر الندى والتعلم
والاستدلال والمراجعة القائمة في مواضعها، ولم تُنشأ نواة قبول موازية.

## حدود السلطة والبيانات

| المدخل أو المخرج | وضعه في هذه الوصلة |
| --- | --- |
| النص الأصلي | محفوظ ببايتاته وبصمته؛ التطبيع لتمثيل الاسترجاع فقط |
| الجذر | يورده المستدعي؛ لا تدعي الوصلة اكتسابه من النص |
| 18 هوية معنى | من `evidence/lexical_denotation/catalog.json` المثبت ببصمته القائمة |
| شواهد التدريب | 36 صفًا: الاقتباس المثبت ووصف المكونات لكل معنى |
| المصادر | شواهد محدودة من لسان العرب ومقاييس اللغة والشخصية الجزء الثالث؛ ليست الكتب كاملة |
| تفسير المكونات | التفسير المؤلف الموجود في الفهرس؛ لم يتحول بالتدريب إلى تفسير محكّم استقلالًا |
| الدرجة العصبية | ترتيب اقتراحي، غير معاير، لا يحدد المراد ولا يمنح سلطة قبول |
| `--target` | مكونات مصرح بها يختبرها العقد؛ لا يدعي النموذج استخراجها |
| نتيجة Lean | مطابقة/تضمن/التزام مشروط بالمكونات وشواهد اللزوم المثبتة |
| معنى غير مثبت | لا ينشئ النموذج له شهادة؛ الجذر غير المثبت يعطي `UNMEASURED_ROOT` |

لا تدخل الدرجة أو ترتيبها أو `argmax` في طلب الفاحص. يستقبل صاحب العقد
الجذر والمكونات كما كان، ويعيد كل المعاني المثبتة. لذلك يستطيع التقرير
أن يعرض اقتراحًا عصبيًا خاطئًا وإيصالًا شرطيًا صحيحًا دون أن يخلطهما.
يبقى `intended_sense_established=false` حتى عند نجاح الفاحص.
غياب التنفيذ أو تعذر الشاهد يبقي حالة العجز ظاهرة؛ لا يحوّلها النموذج
إلى قبول. لا توجد عتبة احتمالية تدعي كشف المعاني الجديدة أو توزيع خارج
التدريب؛ قد يرتب نصًا غير ملائم بثقة عددية مرتفعة.

## النموذج والتجربة المسجلة

نرمّز تكرار الكلمات والمقاطع الحرفية إلى 512 خانة CRC32 مشتركة مع
المسترجع السابق. بعد تحويل التكرار بـ `1 + log(count)` وتطبيع طول
المتجه، يتعلم النموذج:

\[
h=\tanh(xW_1+b_1),\qquad p=\operatorname{softmax}(hW_2+b_2).
\]

الطبقة الخفية 32، والمخرجات 18 هوية؛ المجموع 17,010 معاملًا. دالة
الخسارة هي الإنتروبيا المتقاطعة على هوية المعنى، وليست قرار القبول
المنطقي. التدريب Adam لمدة 700 خطوة كاملة، ببذرة ومعاملات مثبتة في
`evidence/neural_senses_v1/protocol.json`. الدرجات محسوبة على الفهرس
كله ثم تعرض معاني الجذر المطلوب؛ ليست احتمالات معايرة للمراد في سياق.

سجل `run_01/FIRST_TEST.json` أول تدريب، وأوزانه وبياناته وتنبؤاته محفوظة
إلى جانبه. لا تتطابق نصوص التشخيص حرفيًا مع نصوص التدريب، لكنها صياغات
مؤلفة لمعانٍ رآها التدريب، وقد أعدها المؤلف نفسه. ليست اختبارًا محجوبًا
مستقلًا، ولا فصلًا بين جذور التدريب والاختبار.

| التشخيص | الشبكة | أقرب نص معجمي بجيب التمام |
| --- | ---: | ---: |
| جميع الصياغات المؤلفة | 18/18 | 18/18 |
| الجذور ذات المعاني المتعددة فقط | 10/10 | 10/10 |

لا يثبت هذا التشخيص أفضلية عصبية. ثمانية أسئلة ذات جذر لا يضم إلا
معنى واحدًا لا تقيس إزالة اللبس أصلًا. لذلك لم يتغير المسترجع الافتراضي،
ولم تُعدّل المعاملات بعد رؤية نتيجة التشخيص. تقيّم المقارنة ترتيب
المعنى، لا صحة تطبيقه على وقوع عربي جديد ولا صدق القضية في العالم.

## التشغيل وإعادة الفحص

من جذر المستودع، مع Python 3.12 وNumPy 2.3.5 وLean 4.34.1 المثبت:

```bash
python -m pip install numpy==2.3.5
make -f Makefile -f integrations/neural_senses.mk neural-senses LAKE=/path/to/lake

python tools/propose_lexical_evidence.py \
  --text 'أداة نكتب بها' --root 'قلم' \
  --target 'الذي يكتب به' \
  --sense-model evidence/neural_senses_v1/run_01 > /tmp/qalam-proposal.json

python tools/propose_lexical_evidence.py \
  --text 'أداة نكتب بها' --root 'قلم' \
  --target 'الذي يكتب به' \
  --sense-model evidence/neural_senses_v1/run_01 \
  --verify /tmp/qalam-proposal.json
```

تعيد `--verify` الحساب من النص والجذر والمكونات والأوزان المعطاة
استقلالًا، وتقارن التقرير كله، مع إعادة تشغيل الفاحص. يشمل ذلك أصل
النص وحدود السلطة والبدائل والنتيجة الشرطية. المقارنة الرقمية حرفية؛
تبديل الأوزان أو البناء التنفيذي أو فروق حساب العائمة بين بيئات التشغيل
قد يقتضي إنشاء تقرير جديد بدل قبول التقرير السابق. الرمز 2 يعني عدم
اكتمال الفحص أو اختلاف التقرير؛ الرمز 0 لا يعني تعيين المعنى المقصود.

لإعادة التدريب في مجلد جديد، دون الكتابة فوق المحاولة الأولى:

```bash
OPENBLAS_NUM_THREADS=1 python tools/train_lexical_senses.py \
  --output-dir artifacts/local/neural-senses-replay
```

لا يشترط التدريب Lean؛ لذلك يحمل سجل التدريب `native_checked=false`.
الفحص التنفيذي عملية منفصلة تشغلها بوابة `neural-senses`، وتلزم NumPy
والتنفيذ الأصلي حتى لا تتحول اختبارات الربط إلى تخطيات صامتة. أضيفت
البوابة إلى مسار التدريب العصبي الموجود في CI، وتعيد التدريب في مجلد
محلي جديد. بقي `ci.yml` مطابقًا لبصمته في سجل اعتماد الاختبارات المجمد.

## ما تتحقق منه الاختبارات وما يبقى

تفحص الاختبارات استعادة ترتيب الأوزان، ومنع تبديل هويات المخرجات أو
أشكالها أو تمرير NaN، وحفظ النص، ورفض المدخلات غير الصالحة، وحفظ
كل البدائل. يفرض اختبار مضاد درجة قصوى لمعنى القمار في وصف أداة الكتابة،
ثم يتأكد عبر تنفيذ Lean الفعلي أن إيصال الدلالات لم يتغير. وتفحص إعادة
التقرير ضد تغيير النص والجذر والمكونات وادعاء السلطة. يتحقق اختبار
الترميز من ناتج محفوظ للمسترجع السابق، ويكتشف اختبار إعادة الاستخدام
المستهلك الجديد تحت صاحب العقد القائم.

لم يتغير قانون Lean ولا فهرس الشواهد؛ المستعمل هو البرهان المشروط
والتنفيذ الموجودان، لا برهان جديد للشبكة أو تنقيح عام بينها وبين Lean.
الشرح يعرض الشاهد والتفسير المعجمي والفحص المنفذ والبدائل؛ لا يشرح
سبب الدرجة داخل الطبقة الخفية، ولا يجوز عرض اقتباس المصدر كأنه تفسير
سببي للحساب العصبي.

يبقى اتصال `RuleLearning` واعتماد علاقة مكتسبة ثم `QualifiedInference`
ومراجعتها بواسطة `EvidenceLifecycleV1` مرحلة لاحقة ذات شواهد تطبيق
مستقلة. هذه الوصلة لا تعتمد قواعد جديدة ولا تسحب شواهد، ولذلك لا تدعي
إغلاق اختبارات التعلم من المثال المضاد أو اكتساب شروط القاعدة أو مراجعة
مسارات الدعم. الأساس التنفيذي المضاف هو اقتراح معنى مرتبط بهويته
ومصدره، مع بقاء القبول المشروط والبدائل تحت سلطة المسار الموجود.

سجل التحقق في `evidence/neural_senses_v1/validation.json`: نجح 2661
من 2902 اختبارًا في `make test`، وتُخطّي 241 بحسب متطلبات بيئتها،
دون إخفاقات. نجحت بوابة الربط بـ24 اختبارًا دون تخطيات، وبناء Lean
4.34.1، وفحص الاعتماد، وإعادة التقرير. أعاد التدريب في البيئة نفسها
الأوزان ذاتها عدديًا. لم تُشغّل بوابة إصدار `make check` كاملةً؛
التغيير لا يعدل النواة البرهانية ولا يعلن إصدارًا مكتملًا.

سجل المتابعة `ci-followup.json` يحفظ إخفاق CI الأول بسبب تغيير ملف
التشغيل المجمد، ثم إصلاح موضع البوابة داخل مسار التدريب العصبي الموجود.
نجح فحص الملفات التسعين المثبتة دون تغيير سجل اعتمادها، وأضيف اختبار
انحدار يستدعي فاحص الاعتماد نفسه؛ أعيدت بوابة الربط فنجح 25 اختبارًا
دون تخطيات. لم تتغير شيفرة التدريب أو الاستعمال في هذا الإصلاح.
