# التطبيق التجريبي على NABT الحالي

هذا هو المخرج التنفيذي الأول للبرنامج المشروط ذي الاثني عشر أسبوعًا:
**عقد جواب + شهادة تحليل + مجموعة قياس قابلة لإعادة التشغيل**.
يشغل مقترح `tools/verified_reading.py` الموجود، ثم يتحقق برنامج Lean
`verifiedReading` من المصدر والسؤال والإغلاق الكامل. لا يضيف أوزان LLM،
ولا يغيّر القانون أو القارئ أو المدخلات المجمدة، ولا يسجل تدريبًا لم يحدث.

## التشغيل

من جذر المستودع وبأداة Lean المثبتة في `formal/lean-toolchain`:

```bash
lake --dir formal build verifiedReading
python tools/explainable_pilot.py answer examples/verified_reading/source.txt examples/verified_reading/query.txt --output artifacts/local/answer.json
python tools/explainable_pilot.py verify examples/verified_reading/source.txt examples/verified_reading/query.txt artifacts/local/answer.json
make explainable-pilot
```

يقبل `answer --certificate proposal.json` شهادة مقترحة خارجيًا بالعقد الحالي
`nabt.verified-ground-reading.v1`. هذا منفذ ربط نموذج مستقبلي: النموذج يقترح،
والنواة تفحص، والعرض يصدر بعد قبول النواة. لا توجد مكالمة خدمة أو تكلفة
LLM أو تنزيل أوزان ضمن هذا التنفيذ. عند استعمال `--source-id` أو `--revision`
أو `--scope` يجب تقديم القيم ذاتها مستقلّةً عند إعادة التحقق.

الجواب الافتراضي الآن `nabt.explainable-answer.v2`؛ يضيف عقد شرح مشتقًا
من الشهادة المقبولة. يبقى `answer --answer-version v1` لإنتاج الصيغة
السابقة، ويعيد `verify` بناء الإصدار المثبت في الملف. إذا كان المستهلك
يشترط الشرح الجديد، يستعمل `verify --answer-version v2`؛ عندئذ يرفض
ملف v1 ولو كان صحيحًا في نطاقه. تحفظ إعادة فحص v1 شكل إيصالها السابق؛
أما v2 فتعيد `nabt.answer-replay.v2` وهوية عقدي الجواب والشرح.

## عقدا الجواب `nabt.explainable-answer.v1/v2`

| الحقل | العقد |
|---|---|
| `binding` | هوية المصدر ونسخته ومجاله؛ SHA-256 وعدد بايتات UTF-8 لكل من المصدر والسؤال |
| `answer.status` | واحدة من الحالات الخمس أدناه؛ تصدر من التنفيذ الأصلي للنواة |
| `answer.text_ar` | قالب عربي حتمي يصف الحالة، مع السؤال الحرفي وحدود الحكم |
| `analysis_certificate` | شهادة النواة ومقاطع المصدر وشبكتا الاشتقاق وروابط النتيجة |
| `verification` | إيصال التنفيذ الأصلي وبصمة الملف التنفيذي المستخدم |
| `limits` | مجال اللغة، وحدود الحقيقة والتغطية والتفسير السببي والنموذج العصبي |
| `explanation` في v2 | الالتزامات الأربعة، وشروط القواعد وموانعها، والاعتمادات والبقايا المستعادة من الشهادة المقبولة |

`SUPPORTED` يؤيد السؤال، و`REFUTED` يؤيد نقيضه بدليل خال من التعارض؛
`CONFLICT` يحفظ الدليلين؛ `UNKNOWN` يعني عدم اشتقاق الطرفين بعد فحص
الإغلاق الكامل؛ `DEFER` يعني اشتقاقًا متأثرًا بالتعارض بلا دليل نظيف.
القطبية نسبية إلى **السؤال نفسه** حتى إذا كان منفيًا.

الفشل التقني لا يحمل `status`: يخرج `nabt.pilot-error.v1` مع
`INVALID_INPUT` أو `OUTSIDE_VERIFIED_LANGUAGE` أو `RESOURCE_LIMIT` أو
`CHECKER_UNAVAILABLE` أو `CERTIFICATE_REJECTED` أو `ANSWER_REJECTED`، وقد
يظهر `CHECKER_CHANGED` أو `CHECKER_PROTOCOL_ERROR` أو `RENDERER_ERROR` أو
`IO_ERROR`. لا يتحول انتهاء الوقت أو غياب الفاحص إلى `UNKNOWN`.
الخروج صفر لجواب متحقق أو إعادة تحقق ناجحة، و2 لخطأ واجهة الأمر.

ملف الجواب غير موثوق بذاته. `verify` يستقبل المصدر والسؤال والهوية من
المستدعي، ويشغّل النواة مجددًا، ويعيد بناء الجواب والتفسير، ثم يقارن
JSON كاملًا مقارنة تراعي الأنواع. تُرفض الحقول الإضافية وتبديل النص
والهوية والنسخة والمجال والدليل والمقاطع وتحويل عدد إلى boolean.
لا تمنح بصمة أو عبارة `verified` قادمة من الملف سلطة قبول.
تُرفض أيضًا الأعداد غير المنتهية، بما فيها فائض الأس مثل `1e400`،
ومحارف surrogate غير المقترنة، وتجاوز حجم الغلاف، قبل استدعاء الفاحص.
حقول الأعداد في سلك الجواب والشهادة أعداد صحيحة غير سالبة بصيغة عشرية
معيارية؛ تُرفض `-0` والكسور وصيغ الأس قبل أن يمحو فك JSON اختلاف كتابتها.
يرفض الإصدار الأول أيضًا اختلاف بصمة الفاحص: بعد تغيير بنائه أعد إصدار
الجواب تحت الفاحص الجديد بدل ادعاء إعادة تشغيل الملف التنفيذي السابق.

## شهادة التحليل `nabt.analysis-certificate.v1`

`source_clauses` يحفظ النص الحرفي لكل قضية ومعرفها `c0...` ومجال بايتاتها:
بداية صفرية ونهاية مستبعدة. لا تطبيع يزيل تشكيلًا أو يغير المصدر.
`traces.full` و`traces.clean` يحفظان كل خطوة، والقضية المصدرية، وروابط
المقدمات السابقة، والذرة المستنتجة وقراءتها العربية. يعاد ربط فهارس
البرنامج المنقى بالقضايا الأصلية؛ إزالة المتعارضات لا تبدل نسبة الدليل.
`roots` يحدد دليل السؤال ونقيضه في كل شبكة، أو `null` عند غيابه.
كل شبكة محدودة بحد الشهادة الحالية؛ لا نسخ عوديًا لأشجار قد تتضخم.

هذا تفسير **للمصدر والاشتقاق المقبول**، وليس ادعاء كشف السبب الداخلي
لاختيار نموذج عصبي. لا ندعي أصغر دليل، ولا برهان تنقيح Python أو عارضه.
مبرهنات `Nabt.VerifiedReading` القائمة تثبت التنفيذ والقراءة المضبوطة؛
الفحص التنفيذي واختبارات المقاطع وروابط الدليل تتحقق من الغلاف الجديد.
النص المضبوط فقط: قضايا وقواعد أرضية أحادية أو ثنائية، نفي صريح، وتنسيق
حرفي محدد. تحليل النص العربي الحر والغموض والإحالة يبقى في مساره القائم
بحدوده المعلنة، ولا يحوّل هذا الغلاف نتائجه إلى شهادة أوسع.

حدود الواجهة: المصدر 65536 بايت، السؤال 8192، شهادة النواة 1 MiB،
الغلاف 4 MiB، كل حقل هوية 256 بايت، والمهلة الافتراضية 20 ثانية
وبحد أقصى 60. تبقى حدود القضايا والخطوات في [عقد القراءة](VERIFIED_READING.md).
فاحص Lean الموثوق من إعداد المستدعي، لا من مسار داخل الملف؛ نظام التشغيل
والمترجم والتنفيذ الأصلي وJSON وواجهات الملفات ضمن قاعدة الثقة المعلنة.

## عقد الشرح `nabt.explanation-contract.v1`

يبنيه `tools/explainable_contracts.py` بعد قبول المحقق الأصلي. يستعمل
الجمل والمقاطع والإغلاقين وشبكتي الاشتقاق الموجودتين؛ لا يعيد قراءة
النص بمحرك آخر أو حساب إغلاق بديل. الدالة منفردة عارض لبيانات سبق
فحصها، وليست مدخلًا يمنح سلطة لشهادة مقترحة.

| الحقل | ما يعرضه |
| --- | --- |
| `axes.reading_fidelity` | قراءة النص والسؤال حرفيًا في اللغة الأرضية المضبوطة؛ لا توثيق القائل أو قصده |
| `axes.premise_support` | مقدمات مصدرية واشتقاقات مشروطة بها؛ لا صدق خارجي للمقدمات أو القواعد |
| `axes.inference_validity` | حكم المحقق وحقول الدعم والنقيض في الإغلاق الكامل والنظيف |
| `axes.case_applicability` | مطابقة المحمول والأطراف المرتبة والقطبية ومجال المصدر؛ يبقى المناط الخارجي غير مثبت |
| `operations` | كل قضية مصدرية، حتى لو لم يستعملها الدليل المختار؛ موضعها ومدخلاتها ومخرجها وشواهدها وموانعها |
| `conflicts` | الذرة ونقيضها، وشاهد كل منهما، والقضايا التي يتأثر إبقاؤها في البرنامج النظيف |
| `targets` | السؤال ونقيضه، وجذور دليلهما، والقواعد المرشحة والبقايا الخاصة بكل طريق |
| `dependencies` | أسلاف جذر الدليل المحتفظ به في كل شبكة، مع تمييز الوقائع المصدرية عن القواعد |
| `judgment_change` | المدخلات التي يستدعي تغيرها إعادة الفحص؛ لا وعد بحكم معين بعد إضافة مقدمة أو سحبها |

داخل القاعدة الواحدة تبقى المقدمات مجتمعة، وبين قواعد ذات نتيجة واحدة
تبقى الطرق بدائل. `clean_retained=true` يعني بقاء القضية داخل البرنامج
المنقى، ولا يعني أنها نُفذت في الدليل المحتفظ به؛ تسجل `full_steps` و
`clean_steps` الاستعمال الفعلي في ذلك الدليل. إذا تكررت خطوة صحيحة في
شهادة خارجية، تعرض شروط القاعدة أول شاهد سابق متاح، وتحفظ شبكة
الاشتقاق حوافها الفعلية والجذر الأخير.

المقدمة الغائبة عن الإغلاق غير مشتقة؛ لا توصف بأنها كاذبة. وبقايا طريق
مرشح قد تظهر مع وجود طريق مستقل مؤيد. لا يقدم التشخيص أصغر تعديل أو
شرطًا ضروريًا لجميع البراهين. وتنتهي متابعة علاقات القواعد عند العقد
المزارة، فتظل دورة بلا أصل داعم غير قادرة على منح دعم لنفسها.

قبل العرض، يفحص الغلاف شكل إيصال النجاح وأنواعه وتطابق القطبيات مع
شهادة الإغلاق المقبولة وتوافقها مع اسم الحكم. عدم الاتساق خطأ
`CHECKER_PROTOCOL_ERROR`. هذا فحص لواجهة المحقق، ولا يعوض قبول Lean
ولا يصادق على ملف تنفيذي غير موثوق اختاره المستدعي.

المواصفة المثبتة قبل التنفيذ في
[عقد الدفعة](EXPLANATION_CONTRACTS_V1_SPEC.md)، والحالات الجديدة في
`evidence/explanation_contracts_v1/acceptance_cases.json`. تبقى مجموعة
التطوير القديمة ومقاماتها وأجوبتها التاريخية محفوظة. لا يربط هذا العرض
قاعدة مصدر المستخدم بموضع كتاب نحوي لمجرد تشابه لفظي؛ يصل ذلك في
دفعة مستقلة بعد إثبات جسره، وفق
[الخطة الدائمة](NABT_EXPLANATORY_METHOD_PLAN_AR.md).

## القياس الحالي والأهداف

تشغّل `tools/evaluate_explainable_pilot.py` أربع عشرة حالة معلومة، بينها
مثال المستودع والحالات الخمس والعلاقات والنفي والتشكيل والتكرار؛ ثم أربع
حالات حذف مقدمات، وأربع عشرة محاولة تلاعب مسماة. مصادرها من أمثلة
المستودع واختباراته، مع حالات عرض وحذف مؤلفة. هي **مجموعة تطوير مكشوفة**؛
ليست اختبارًا محجوبًا ولا عينة جديدة مستقلة من العربية.

يسجل التقرير المقامات، كل حالة وفشلها، بصمات الشيفرة والمدخلات، نسخة
Python والمنصة والفاحص، وكل عينة زمن. تعريف الدقة الحاسمة: الأجوبة
الصحيحة من `SUPPORTED/REFUTED` مقسومة على جميع الأجوبة الحاسمة؛ وتغطيتها
عددها مقسوم على جميع الحالات الأربع عشرة، بما فيها التعارض وعدم المعرفة.
رفض التلاعب ليس مقياس قبول دلالي خاطئ، واجتياز الحذف ليس قياس تفسير بشري.
المقارنة الزمنية بين المقترح القائم مع فحص النواة وبين الغلاف مع النواة
والعرض، على الجهاز نفسه؛ لا مقارنة بنموذج لغوي أو عتاد آخر.
يعيد القياس الفاشل حالة خروج غير صفرية، وتبقى المقاييس غير المنفذة `null`.
أخطاء المقترح المتوقعة تحفظ سجل كل حالة ومقامها؛ وعند تعذر إعداد اختبارات
التلاعب، تبقى المحاولات الأربع عشرة مسجلة بأنها لم تنفذ، ولا يتقلص مقامها.

| البوابة | المقياس والهدف | الحالة عند بدء هذا التطبيق |
|---|---|---|
| العقد | 100% إعادة تحقق ومطابقة بايتات على مجموعة التطوير؛ صفر تلاعب مقبول | قابل للتشغيل الآن، والنتيجة في سجل القياس |
| الدلالة | دقة حالات ≥90% على اختبار عربي محجوب مجمد قبل التشغيل | غير مقاس في هذه المجموعة |
| الإجابة الانتقائية | دقة ≥99% عند تغطية ≥80%؛ إعلان فواصل ثقة 95% | غير مثبت بعينة التطوير الصغيرة |
| القبول الخاطئ | صفر قبول غير مستند على ≥3000 مثال سلبي مستقل ومتنوع | الأربع عشرة محاولة لا تحقق هذا الهدف |
| التفسير | ≥98% توافق تفسير/دليل في مراجعة مستقلة، مع اتفاق مقيمين | الاختبار التنفيذي فقط متاح الآن |
| الأداء | زمن P95 ≤1.5× خط الأساس وتكلفة ≤ خط الأساس على العتاد المتفق عليه | عينات محلية متاحة؛ تكلفة LLM غير مقاسة |
| التوسعة | تحسن مقاس مع ثبات بوابات السلامة قبل زيادة الحجم أو التدريب | لا تحسن لغوي من إضافة الغلاف وحدها |

المستهدفات البحثية شروط قرار مستقبلية، لا حدود نجاح زائفة لتقرير اليوم.
تحفظ [الأهداف بصيغة آلية](../evidence/explainable_pilot/goals.json) أيضًا
شرط التوسعة المقترح: زيادة التغطية بنقطتين مئويتين على الأقل عند دقة
≥99%، وحد أدنى موجب لفاصل ثقة 95% للفارق المقترن، مع ثبات بوابات السلامة
وميزانية البحث والعتاد. يختار التحقق المنفصل النموذج، لا الاختبار المحجوب.
مع صفر خطأ في 3000 تجربة مستقلة، الحد الأعلى الأحادي 95% لمعدل الخطأ
هو `1 - 0.05**(1/3000)` تقريبًا 0.10%؛ لا يعني انعدام الأخطاء عمومًا.
ولا نفترض استقلال أمثلة مولدة متقاربة لكي نستخدم هذا الحساب.

يعاد تشغيل مجموعة العربية الحرة المجمدة القائمة بصورة منفصلة، وتحفظ
نتيجتها مع تعريفها الأصلي. لأنها منشورة وسبق فحصها وتعديل النظام بعد
رؤيتها فهي انحدار تاريخي لهذا البرنامج، مهما احتوى اسمها على `holdout`.
لا تختلط درجاتها مع درجات القراءة المضبوطة أو مع أي اختبار محجوب جديد.

## جدول الاثني عشر أسبوعًا المشروط

تبدأ المدة بعد توفير الفريق والبيانات المصرح باستعمالها والعتاد. التطبيق
الحالي ينجز أساس المخرج الأول دون الادعاء بانقضاء أي مرحلة زمنية.

| المدة | المخرج وشرط الانتقال |
|---|---|
| 1–2 | اعتماد العقد ومجموعة القياس وخط الأساس؛ تجميد اختبار مستقل لدى المراجع، وفصل التدريب بالمصدر والوثيقة والقالب |
| 3–4 | ربط نموذج موجود بمنفذ الشهادة؛ كل اقتراح يفحص بالنواة؛ قياس فشل التحليل والبحث والموارد منفصلة |
| 5–8 | مقارنة الاسترجاع والتقييد والتدريب الخفيف على شواهد صحيحة؛ لا تكبير إلا لتحسن متكرر على تحقق منفصل وبكلفة معلنة |
| 9–12 | تشغيل محجوب واحد، مراجعة مستقلة للتفسير وحدود اللغة، تقرير ثقة ومقامات وكلفة؛ قرار استمرار أو إيقاف |

لا يكفي تحسين نسبة نجاح براهين اقترحها النموذج لإثبات تحسن الترجمة من
العربية إلى المنطق. لذلك يحتاج الاختبار المستقل أيضًا حكمًا على صحة
الإسقاط الدلالي وحفظ القراءات قبل الاستدلال. غياب البيانات أو العتاد
يؤجل هذه الأهداف، ولا يعوّض بإعادة تسمية أمثلة التطوير «محجوبة».
