# بوابة NABT الوحيدة للتكامل الخارجي

تدخل التطبيقات والوكلاء وواجهات RAG من `tools.grammar_catalog gateway`.
تعيد البوابة استخدام أصحاب العقود الحاليين، وتربط الجواب بفهرس البرهان
الحالي ومصادره واختباراته. لا تنقل المختبر السابق ذا المقدمات المؤلفة
إلى الإنتاج، ولا تنشئ قارئًا أو جبرًا لغويًا موازيًا.

تصل [وصلة الدلالة وOntoLex](RATIONAL_RAG_ONTOLEX_AR.md) الفاحص المعجمي
القائم بالمسارين `lexical.assess` و`lexical.ontolex`؛ تحفظ المعاني البديلة
والشواهد، وتعرض المطابقة والتضمن والالتزام ضمن شروط التفسير المثبت.

## التشغيل والقبول

من جذر مستودع NABT، مع Python 3.11 أو أحدث:

```sh
PYTHONPATH=src:. python -m tools.grammar_catalog gateway catalog --output artifacts/local/io-catalog.json
PYTHONPATH=src:. python -m tools.grammar_catalog gateway run --request examples/io_gateway/contrast.json --output artifacts/local/io-receipt.json
PYTHONPATH=src:. python -m tools.grammar_catalog gateway verify --request examples/io_gateway/contrast.json --receipt artifacts/local/io-receipt.json
```

الطلب ذو الحقول الثلاثة فقط:

```json
{
  "schema": "nabt.io.request.v1",
  "route": "grammar.search",
  "payload": {"query": "اسم الفاعل", "limit": 5}
}
```

تخرج النتيجة في `nabt.io.result.v1`. يحتفظ المستهلك بطلبه مستقلًا ويستدعي
`gateway.accept_output(receipt, expected_request=request)` أو أمر `verify`.
يعيد هذا الفحص تشغيل صاحب العقد ويقارن الجواب الكامل، بما فيه روابط
البرهان والاختبارات وبصمة المصدر. يُرفض جواب المالك الخام، وتزوير الحقول
ولو أُعيد حساب البصمات، وتغيير الطلب أو المصدر. نجاح التحقق يثبت إعادة
النتيجة الحالية في نطاق الطلب؛ لا يرفع رتبتها الدلالية.

تعني `EXECUTED` أن استدعاء المالك اكتمل. القرار اللغوي والمعرفي الأصلي
داخل `execution.owner_result` وقد يكون إرجاءً أو تعارضًا أو نقصًا في
المقدمات. نتائج الموارد مستقلة عن الرفض الدلالي. رمز خروج `run` صفر
للتنفيذ، و٣ لعدم اكتماله؛ ورمز `verify` صفر للقبول و٢ لعدم القبول.
أخطاء المدخل لها غلاف `nabt.io.error.v1` ولا تقبل بوصفها جوابًا مرخصًا.

## المسارات وأصحاب العقود

| المسار | صاحب التنفيذ الحالي | نوع الشاهد |
|---|---|---|
| `relations.search` / `relations.analyze` | `relational` فوق الاشتقاق والإعراب والمنهج والزمن و`mantuq.source` | [مصفوفة الأجناس والخواص والعلاقات](RELATIONAL_RAG_V1_AR.md)، مع حفظ واجبات الربط الأنطولوجي |
| `operation` | `operation_rag` ثم `operation_runtime` | ١٣ عملية مصنفة مع نتائجها الأصلية |
| `grammar.search` / `grammar.route` | `retrieval` / `routing` | استرجاع ثم جدولة قواعد مع بديل كامل |
| `awamil.search` / `awamil.analyze` / `awamil.check` | `awamil` / `awamil_cli` | مصادر العوامل والعلاقات وشروط التطبيق |
| `agents.search` / `agents.gate` | `lexical_training.agent_plan` | المتطلبات والبوابة القائمة |
| `agents.transport` | `unicode_transport` | البايتات الأصلية والتحويل القابل للفحص |
| `units.search` / `units.run` | `unit_catalog` / `arabic_training.unit_composition` | A116 وتركيب الوحدات بشروط المالك |
| `irab.search` / `irab.analyze` | `irab` | العلامة والدور والبدائل |
| `application.analyze` / `application.temporal` | `application` / `temporal` | وصل النص والتحليل والمقام والزمن |
| `mantuq.search` / `mantuq.source` | `mantuq_inference.retrieval` / `source_bound` | مصادر المنطوق والمفهوم والنتيجة الأصلية بفاحص Lean |

تصل عملية `lesson` داخل مسار `operation` إلى منسق الدروس الموجود في
`lexical_training.teaching`. تُستعاد مصفوفات المنهج والأساس المشترك من
`reasoning_curriculum.matrix`، وتُحل أسماء مالكيها إلى الفهرس نفسه:
التفكير والشخصية ١ و٣، والاستدلال العقلي، والقياس المعرفي، والتعلم من
المصدر، والمقام والزمن. تبقى سلطتها `CURRICULUM_ONLY`، وتُحفظ التزامات
اكتساب المعنى والتطبيق؛ تسميات المجالات لا تمنح سلطة للدليل.

يحمل `mantuq.source` النص الأصلي وطلب الاستفهام وخطة الأدوار الموجودة؛
لا يقبل مسارات فواحِص من العميل. تبقى الخطة تعيينًا مقدمًا للفحص، ولا
يحوّلها نجاح النقل إلى صحة دلالية. تستخدم القراءة `verifiedReading`
و`classicalSemanticProbe` المثبتين. يحفظ الغلاف كل الشواهد النظيفة
والكاملة وشروط النتيجة التي أعادها المالك.

## فهرس واحد وجسور معلنة

السلطة المصرح بها للأسماء هي `formal/theorems.json`؛ والعبارات المجمعة
وبصماتها ومحاورها من الفهرس الذي يحدده `integrations/current_proof_references.mk`.
تستدعي البوابة `current_catalog` و`build_reuse_report` للتحقق من المصدر
والفهرس. لا تنسخ الأسماء إلى قائمة ثابتة جديدة.

تشتق `gateway_links` ثلاثة أنواع من الحواف:

1. مصدر RAG إلى تصريح مسمى: باستعمال مؤلف الروابط الموجود في
   `grammar_catalog.links` و`mantuq_inference.links` دون مطابقة تخمينية.
2. تصريح إلى عائلة برهان: من جرد إعادة الاستعمال الحالي، مع الاسم
   القانوني وبصمة العبارة.
3. عائلة إلى ملفات اختبار وفواحِص: من السجل نفسه، مع بصمة الملف
   وأسماء طرائق الاختبار المستخرجة منه.

العلاقة الثالثة ارتباط معلن على مستوى العائلة، وليست شهادة تغطية لكل
مبرهنة. وجود اسم اختبار لا يعني تشغيله؛ يظل `test_execution_performed=false`
في الجواب. تسجل CI ومخرجات الفحص التشغيل الحقيقي منفصلًا. تبقى سجلات
المصدر التي لا تحمل رابط مبرهنة، والتزامات الجسور المفتوحة، ظاهرة.
لا تُفهم فجوة الربط بوصفها حكمًا على صحة النص أو نفي وجود قدرته التنفيذية.

## حدود التنفيذ والإصدار

الحد الأعلى للطلب ٢ MiB وللنتيجة ٨ MiB؛ العملية الفرعية محددة بـ٣٠ ثانية
جداريًا و٢٠/٢١ ثانية CPU و٤ GiB للذاكرة الافتراضية. تعاد الاستفادة من
ناقل `operation_rag` الموجود، مع اسمي عامل ثابتين. قد يحدّد المالك ميزانية
أشد. تزال متغيرات `NABT_*` من بيئة العامل؛ لا يختار العميل ملفًا تنفيذيًا
أو وحدة Python. بصمة التشغيل تربط مصادر التنفيذ وLean والفهرس والاختبارات
وتعليمات التطوير ووصفات التكامل وCI. اختلاف توافر الثنائيات يغيّر البصمة.

تُحفظ بصمات الثنائيات داخل العملية حسب هوية الملف وحجمه ووقت تعديله
وتغييره، وتُعاد عند تغيرها. هذا حفظ لبصمة الملف؛ نتائج المالك لا تُخزّن
بدل إعادة التشغيل. ينفذ مسار العمليات داخل العامل المحدود نفسه كي
لا ينشئ مجموعة عمليات منفصلة عن حد الإنهاء الخارجي.

هذه حدود تكامل للبرمجيات المستهلكة. لا تمنع مبرمجًا يملك المستودع من
استدعاء دالة داخلية؛ ولا يُعرض ناتج تلك الدالة بوصفه خرج NABT الخارجي.
تبقى واجهات `nabt` والأدوات القديمة داخلية لفحوصها المجمدة. كل إضافة
خارجية تمر بمحوّل ثابت هنا وبالقبول المستقل، وفق `AGENTS.md`.

```sh
make io-gateway
make io-gateway-native LAKE=/absolute/path/to/lake
make check LAKE=/absolute/path/to/lake
```

يجمع `GNUmakefile` بوابة الإصدار القديمة مع فهرس البرهان واختبارات
المنطق والقراءة والبوابة. يتطلب فحص البوابة الأصلي الثنائيات السبعة
ويفشل عند غيابها؛ الفحص الخفيف يصرح بتخطيها. لا يثبت هذا التغيير
تنقيح Python إلى Lean أو اكتمال العربية، ولا يدرب نموذجًا لغويًا جديدًا.
المضاف هو وصلة تشغيل وقبول عبر العقود والمبرهنات القائمة.
