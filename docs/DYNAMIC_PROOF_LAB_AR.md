# مختبر NABT الديناميكي

يتيح المختبر إدخال نص وقضية، ثم تشغيل القانون المثبت
`nabt.licensed-inference.v1` داخل GitHub Actions. يستعمل العامل التنفيذي
مقترح Python ومدقق Lean الأصلي الموجودين في المستودع. لا يفسر المدخل بوصفه
شفرة، ولا يقبل من المستخدم قاعدة جديدة أو مسار ملف أو اسم برنامج تنفيذي.

النتيجة شهادة تنفيذ بالنسبة إلى النص والقانون المحدد؛ ليست إثباتًا لصدق
النص في العالم، ولا برهانًا على اكتمال العربية كلها. لا يضيف المختبر قانونًا
لغويًا أو مبرهنة Lean، بل يوصل الواجهة إلى المسار المفحوص القائم.

## الاختباران

1. **فحص عبارة وقضية:** يقرأ المدقق النص والقضية الأصليين ويعيد نتيجة
   الاستدلال وقراءاته وشهادات الإغلاق. تبقى حالات عدم المعرفة، وتعارض
   الأدلة، وخروج العبارة عن النطاق، وغياب المدقق، ونفاد الموارد متمايزة.
2. **إعادة قياس المجموعة المستقلة:** يعيد تنفيذ الحالات الثماني والثلاثين
   المثبتة ببصمة `independent_gold.json` باستخدام المقيم القائم. يعيد جميع
   الصفوف، بما فيها الفشل وغير المقاس، ولا يسمح باستبدال الإجابات المرجعية
   بمدخلات المستخدم. نسبة النجاح تخص هذه المجموعة فقط؛ لا تسمى نسبة اكتمال
   العربية.

النطاق اللغوي المثبت هو `nabt.explicit-subject-active.v1`، وفيه أفعال وأعلام
وظروف محدودة، وقراءة معلنة للمعلوم. لا يستنتج نفي الجواب من نفي الشرط. لا
يربط الضمير المستتر بفاعل الجملة تلقائيًا. راجع
[نطاق القانون والأدلة](LICENSED_INFERENCE_AR.md) و
[حدود التقييم المستقل](LICENSED_INFERENCE_BENCHMARK_AR.md).

## عقد الطلب

معرف الطلب UUID من النسخة الرابعة، بصيغته القياسية الصغيرة. يرسل منفصلًا
عن النص `payload` الآتي:

```json
{
  "schema": "nabt.proof-lab-request.v1",
  "mode": "inference",
  "source_text": "إِنْ عَرَفَ زَيْدٌ الْحَقَّ سَارَ زَيْدٌ. عَرَفَ زَيْدٌ الْحَقَّ.",
  "query_text": "هَلْ سَارَ زَيْدٌ؟",
  "budget": {
    "max_clauses": 64,
    "max_readings": 64,
    "max_atoms": 256,
    "max_closure_steps": 256
  }
}
```

الحقل `budget` اختياري. هذه القيم سقوف واجهة، ويمكن خفضها إلى الصفر لاختبار
حد الموارد. لا يقبل مكان العدد الصحيح قيمة منطقية أو عددًا عشريًا. يقبل
طلب التقييم حقلين فقط:

```json
{"schema":"nabt.proof-lab-request.v1","mode":"benchmark"}
```

| الحد | السقف |
| --- | ---: |
| حمولة JSON بترميز UTF-8 | 32768 بايت |
| النص | 16384 بايت |
| القضية | 4096 بايت |
| العبارات | 64 |
| القراءات | 64 |
| الذرات / خطوات الإغلاق | 256 لكل منهما |
| النتيجة قبل التشفير | أقل من 2 MiB |
| زمن مهمة GitHub كاملة | 10 دقائق |

يرفض القارئ مفاتيح JSON المكررة، والأعداد غير المنتهية، وUnicode التالف،
والحقول غير المعروفة. تحسب البصمة على بايتات JSON الأصلية بعد فك التشفير،
بما فيها الفراغات وترتيب المفاتيح، ولا تحسب على إعادة تسلسل تطبيعية لها.

عند التشغيل عبر GitHub، لا يرسل هذا النص مكشوفًا. القيمة الخارجية لـ
`payload` غلاف `nabt.proof-lab-envelope.v1`، يحوي `nonce` و`ciphertext`
بترميز Base64 القياسي. التشفير AES-256-GCM، ببادئة عشوائية جديدة من 12 بايتًا
لكل رسالة، ومعرف الطلب `request_id` بياناتٍ مصادقًا عليها (`additionalData`).
يضم `ciphertext` وسم المصادقة ذي 16 بايتًا. تنمو النتيجة المشفرة بنحو الثلث
بسبب Base64، فيلزم حد نقل منفصل أكبر من حد JSON المفكوك.

## عقد النتيجة

المخطط `nabt.proof-lab-result.v1` يحمل `request_id` و`payload_sha256` و
`code_sha` و`native_sha256` وبصمتي الموجه والمنفذ، ووقت التنفيذ ومدته ونطاقه.
في الفحص المفرد يحمل `result` استجابة `evaluate()` الأصلية. في القياس يحمل
`benchmark` الملخص وعقد النزاهة وجميع الصفوف الثماني والثلاثين، مع حذف
الاستجابات الخام المطولة ولقطات البيئة من غلاف النقل فقط.

تظل `all_arabic_complete=false` و`world_truth_established=false` في الغلاف.
إذا ادعت استجابة المحرك خلاف ذلك، أو ادعت التحقق دون الفحص الأصلي واكتمال
الإغلاق داخل النطاق، يرفض الموجه النتيجة. يعاد فحص هوية الالتزام والمدقق
والموجه والمنفذ بعد التشغيل؛ تغيرها يمنع إصدار النتيجة. بصمة الملف أداة
ربط وتحقق من سلامة النقل، وليست بذاتها مبرهنة دلالية.

حالات النقل الخاصة تشمل `INVALID_INPUT` و`VERIFICATION_UNAVAILABLE` و
`EXECUTION_FAILED` و`RESOURCE_EXHAUSTED`. وفي القياس، تعني
`BENCHMARK_COMPLETE` أن عقد التنفيذ والنزاهة نجح؛ قد يبقى `summary.fail`
أكبر من الصفر. لا تحول هذه الحالة إخفاق التغطية إلى نجاح.

## التشغيل في GitHub

ملف `.github/workflows/proof-lab.yml` مستقل. يشغل اختبار دخان عند رفع فرع
المختبر، ويقبل `workflow_dispatch` بمدخلي `request_id` و`payload`.
يقرأ السكريبت ملف الحدث عبر `GITHUB_EVENT_PATH`؛ لا يدرج المدخلات داخل
أوامر Shell. يثبت Lean 4.34.1 بعد التحقق من بصمة الأرشيف الرسمي، ويبني
`licensedInference`، ثم يرفع ملفًا واحدًا باسم `result.json` داخل أثر
`nabt-lab-<request_id>` لمدة سبعة أيام. الملف نفسه غلاف مشفر جديد؛ ليست
النتيجة مكشوفة داخل ملف ZIP. لا يمنح العامل صلاحية كتابة محتويات المستودع،
ولا يطلب رمز وصول المستخدم. يمرر سر النقل `NABT_LAB_TRANSPORT_KEY` فقط إلى
خطوتي إعداد الطلب وتنفيذه عند الاستدعاء اليدوي؛ لا يمرر إلى اختبارات PR.

الاختبار طلب تشغيل عن بعد داخل عامل GitHub: تفك النصوص في ذاكرته وملفاته
المؤقتة لتدخل مدقق Lean. تحمي طبقة النقل المدخلات والآثار من الظهور العام
في المستودع العام. لا يطبع الموجه النصوص أو بصماتها في سجل الاستدعاء؛ يطبع
المعرف وحالة النقل العامة فقط. تبقى بيانات التشغيل، مثل المعرف والوقت
والالتزام، ظاهرة. لا يدخل مفتاح التشفير أو رمز GitHub المستودع أو حزمة
المتصفح. يعتمد هذا أيضًا على حماية إدارة أسرار GitHub وSites وصلاحيات
من يستطيع تعديل مسار العمل. إذا فقد المفتاح أو فشلت المصادقة، لا توجد
عودة تلقائية إلى نقل مكشوف.

اختبار الدخان وحده يستخدم بيانات اصطناعية معلنة ويحتفظ بنتيجة مكشوفة
باسم `nabt-lab-smoke`. هناك مهمة نشطة واحدة لكل فرع؛ يحتفظ GitHub بمهمة
معلقة واحدة في مجموعة التزامن، وقد يستبدلها طلب لاحق. لذلك تعرض الواجهة
إلغاء المهمة بوصفه فشل تشغيل، ولا تسجله حكمًا لغويًا.

## إعادة التحقق محليًا

```bash
# القفل التالي لبيئة Linux x86_64 / CPython 3.12 المستخدمة في GitHub.
python -m pip install --require-hashes --only-binary=:all: -r integrations/proof_lab/requirements.txt
lake --dir formal build licensedInference
PYTHONPATH=src:. python -m unittest discover -s tests -p test_proof_lab.py -v
python tools/proof_lab.py \
  --request-id 00000000-0000-4000-8000-000000000001 \
  --request-file /path/to/request.json \
  --output /path/to/result.json
```

يمكن استبدال `lake` بمسار التوزيعة الرسمية المثبتة. وجود المدقق شرط لاختبارات
النهاية إلى النهاية؛ إذا لم يبن، تصرح الاختبارات بذلك، ويعيد طلب المختبر
`VERIFICATION_UNAVAILABLE` ولا يمنح شهادة.

## واجهة الويب وحالة التفعيل

مصدر الواجهة والخادم واختباراتهما في `integrations/proof_lab/site/`.
التصميم عربي من اليمين إلى اليسار، مع أمثلة مشكولة، وحدود بحث قابلة للخفض،
وتقرير تنزيل JSON، وتبويب يعيد قياس الحالات الثماني والثلاثين. خط الأساس
المعروض قبل التشغيل لقطة مسجلة، ولا يعرض بوصفه نتيجة تنفيذ جديد.

تعمل الصفحة الخاصة خلف مصادقة Sites. يحتفظ المتصفح بمعرف متابعة الطلب
الموقّع في جلسة الجهاز فقط؛ لا يخزن النصوص أو رمز GitHub في حزمة الواجهة.
يمر الطلب عبر الخادم، الذي يقيّد المستودع ومسار العمل والفرع، ويرفض اختلاف
رأس الفرع عن `NABT_CODE_SHA`. يطابق النتيجة مع معرف الطلب وبصمة JSON
المسلسل على الخادم ونسخة الشفرة، ثم يعرضها. القارئ الطرفي يرفض JSON
المكرر؛ واجهة HTTP تقرأ الكائن ثم تنشئ له تمثيل النقل القانوني مع حفظ
نص المصدر والاستعلام حرفيًا. فحص ZIP والبصمة والتشفير ضمان نقل، لا برهان
على فهم النص.

إعدادات الخادم، بأسمائها فقط:

- `NABT_GITHUB_TOKEN`: سر للوصول إلى مستودع NABT وتشغيل Actions وقراءة الأثر.
- `NABT_SIGNING_KEY`: سر توقيع معرّفات المتابعة.
- `NABT_TRANSPORT_KEY`: مفتاح AES-256-GCM بصيغة 64 رمزًا سداسيًا صغيرًا.
- `NABT_LAB_TRANSPORT_KEY`: الاسم المقابل للمفتاح نفسه في أسرار GitHub Actions.
- `NABT_REF`: `codex/dynamic-proof-lab` في هذا الإصدار.
- `NABT_CODE_SHA`: الالتزام المراجع الذي يحتوي هذا المشغّل.
- `NABT_EXECUTION_ENABLED`: لا يبدأ التنفيذ إلا إذا كانت قيمته `true`،
  واكتملت بقية الإعدادات. القيمة غائبة افتراضيًا؛ لا يوجد تشغيل مكشوف بديل.

**حالة التسليم الأول:** التفعيل الحي متوقف ببوابة صريحة لأن مراجعة الموافقة
الآلية رفضت إعداد سر النقل المشترك دون إذن مخصص لتخزينه لدى GitHub وSites.
الشفرة واختبارات التنفيذ المحلي مكتملة؛ لا ندعي تشغيل طلب مستخدم حي عبر
الصفحة قبل الموافقة وإكمال إعادة الاختبار. يضاف إثبات التشغيل المنشور
بعد تفعيل هذه البوابة. لا تعدّل هذه الحالة نجاح اختبارات النواة السابقة.

لإعادة فحص الخادم دون أسرار أو اتصال خارجي:

```bash
node --test integrations/proof_lab/site/tests/*.test.mjs
cd integrations/proof_lab/site
bash scripts/build.sh
node scripts/validate-artifact.mjs
```

تراجع اختبارات النقل 46 حالة تشمل التشفير والتلاعب بالمعرف والبصمات والـZIP
وعدم كشف الرموز، والحدود العددية، ومنع ترقية أعلام السلطة. واختبارات Python
29 حالة منها تنفيذ مشفر فعلي بنواة Lean، وقياس المجموعة المستقلة من جديد.
هذه اختبارات هندسية محددة، ولا تعادل مبرهنة اكتمال العربية.

نجحت أيضًا 11 حالة لواجهة المستخدم، بما فيها التمييز بين الشهادة والجواب،
وإظهار النتائج القديمة بعد تعديل المدخلات، واستئناف المتابعة دون إعادة إرسال،
والتوقف بعد تكرار تقرير غير مطابق. المجموع 86 اختبارًا محليًا ناجحًا.

## مرصد الأدلة — تطوير الواجهة

أصبح «مرصد الأدلة» تبويب البداية. يستورد سجلات الطبقات الأربع وتقارير
NABT ويعيد حساب هوية النص واتساق الادعاءات والمراحل داخل المتصفح، مع
عدسة مستقلة لكل ادعاء ومقاييس لا تختزل إلى نسبة اكتمال عامة. العينة
الابتدائية مقتطف معلن من سجل «ذهب الولد» الذي زوده المستخدم. النتائج
المستوردة لا تُمنح سلطة قناة Lean الحية، ولا تُرفع الملفات. راجع
[تفاصيل المرصد وحدوده](EVIDENCE_OBSERVATORY_AR.md).

هذا التحديث لا يفعّل سر النقل المعلّق ولا يغيّر جمهور الصفحة الخاصة.
