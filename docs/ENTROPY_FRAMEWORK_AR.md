هذا تنفيذ تنظيمي إضافي في `tools/entropy_framework`، لا قانون قبول لغوي
جديد ولا بديل للفواحص الأصلية. يحافظ على استقلال NABT وحدوده في
`AGENTS.md` و`docs/ARCHITECTURE.md`.

## خط الأساس والمصالحة

يثبت السجل `registry.json` أساس التطوير عند
`b7442580e7e681a68a85f40bc247be8ee286e7e3` بعد دمج PR57، ويحفظ التدقيق
السابق عند `b5f5bf1e…` بوصفه تاريخًا منفصلًا. نتيجة v3 الموثقة في

لا يعني أن مصفوفة200 لم تقس. حالة قياس القدرة الجزئية محفوظة مستقلة في
`scoped_capabilities` و`evidence_records`. مصدر ومواصفة وبروتوكول

ثم المصفوفة المستقلة ذات200 حالة في `7ca87dcda09427641ad346fa1108eb2c87382f22`.
لذلك مجموعة G1 موسومة `frozen` وبصمتها مثبتة؛ مجموعات G2/G3/G4 لم تنشأ بعد.
لا ينقل قياس 25 حالة التشخيصي أو قياس v3 إلى مقام هذه المجموعات.
توسعة `ProductiveClauseV1` مستقلة في نطاقها: فعل «ضرب» ومعجم
أعلام محدود وVSO/VOS؛ مئة سطح موجب تمثل خمسين إطارًا بنسختين كتابيتين.
يجب نشر مقام الأطر ومقام الأسطح منفصلين لأنهما ليسا مئة شاهد مستقل.
التنفيذ المحدود مقاس، وحالة القدرة `EVALUATED`. نجحت إعادة review1

سلامة ربط التنفيذ بالتجميد صادقة في تقرير التشغيل. بقيت محاور الخلايا
والمواضع غير مقاسة للحالات الخمسين خارج النطاق، كما حدد البروتوكول؛ لا
تدخل في رصيد النجاح. الإعادة مكشوفة بعد تصحيح ترتيب إسقاط الأدوار في
المقيّم بحسب مواضع الكلمات، مع حفظ الذهب والمخرجات الأصلية؛ ليست اختبارًا
أعمى أو تعميمًا على معجم محجوب أو شهادة على صدق الواقع.

نجاح شروط الجزء لا يغلق G0 أو GM أو بوابة إصدار المشروع. تبقى تلك البوابات
بحاجة إلى تحقق عقودها واعتماداتها العامة، ولا تعيد نتيجة الجزء كتابة
baseline التاريخي. سُجلت النتيجة بوصفها PASS لتشغيل عقدها المحدود، لا PASS
لبوابة المشروع. أداة الإطار تعرض الدليل ولا تعيد تشغيله أو تصدقه بذاتها.

حالات بنود العمل تعكس هذا الفرق: تسليم السجل وعقد المرشح وأداة القياس
وقواعد الجزء ووصل الشهادة والتحصيل وتقييم المصفوفة، وبقاء بروتوكولات المجموعات
الأخرى والعمل الواسع غير مكتمل. لا يعد تنفيذ الجزء إغلاقًا لـG0 العام.

التوفيق مع `docs/ROADMAP.md`: هذا تقدم محدود في N2 لحفظ المصدر والمواضع،
وفي N4-ب2 لتعيين المعجم والتركيب في الجزء المعلن، ويصل بحدود N6-أ القائمة.
لا يحقق شرط N2 ذي400 واقعة ولا يغلق N4 العام أو سحب الشواهد العام أو
N6-ب الخاص بصدق الواقع واستقلال النقل.

## المسؤوليات والبوابات

السجل يربط ستة أدوار وثماني طبقات وثمانية عشر بند عمل وسبع بوابات:

| البوابة | النطاق |
|---|---|
| G0 | اتصال المصدر بالشهادة |
| GM | عد السجل المحدود ووضوح المقام |
| G1 | الجزء الفعلي ومجموعة 200 |
| G2 | الوضع والعرف ومجموعة 120 |
| G3 | الاستقامة والنفي والحصر في 80 زوجًا |
| G4 | الشواهد المؤهلة والتعارض في 40 سيناريو |
| GR | إصدار محدود متصل، بفحوصه المطلوبة |

حالة العمل مستقلة عن حالة البوابة وعن نوع الدليل. يمكن تسليم الكود
والبوابة غير مقاسة أو فاشلة. التحقق الحالي يفحص المعرفات والمراجع والدورات
والمقامات والمسؤول والمراجع والحالات المعلنة، ولا يشغّل الفحوص المشار إليها.

عند إعلان PASS يطلب الفاحص سجل دليل ومجموعة مجمدة وهوية تشغيل ومقامًا غير
فارغ وصفر فشل/تجاوز/فحص مفقود، وتطابق النطاق والمجموعة. لكنه يظل يفحص
**اتساق إعلان PASS**: يمكن أن تكون جميع البيانات مختلقة ومتسقة. لذلك يخرج
التقرير `evidence_verified=false` و`release_admission=NOT_EVALUATED`
و`semantic_authority=NONE` دائمًا. ربطه بفاحص مستقل يعيد تنفيذ الأدلة عمل
لاحق؛ لا يؤذن بالإصدار من هذا التقرير وحده.

### إضافة نتيجة الجزء بعد تشغيله

1. تحفظ نتيجة التنفيذ الأولى وfreeze وأمر التشغيل في مسار دليل جديد؛ لا
   يعاد تحرير الذهب أو مصدره أو بيانات baseline التاريخية.
2. يضاف سجل إلى `evidence_records` بمعرف فريد و`gate_id=G1` والنطاق نفسه،
   وهوية المجموعة المجمدة والمقيّم والمترجم والكود ونتائج الفحوص المطلوبة.
   `reported_outcome` يصف تشغيل العقد المحدود ويظل إعلانًا يحتاج فحصه الأصلي.
3. تربط القدرة `productive-clause-v1` ذلك المعرف في `evidence_ids` وتصبح
   `EVALUATED`. يعرض التقرير هذه النتيجة في `scoped_capabilities`، دون
   تحويلها تلقائيًا إلى PASS للبوابات أو تغيير baseline. لا تكفي نتيجة هذا
   الجزء لإغلاق G0 أو GM العامين.
4. لا تتغير حالة بوابة كاملة إلى PASS إلا بعد استيفاء عقدها واعتماداتها
   ومراجعة أدلتها. إن اختلف نطاق النتيجة، يسجل عقد قياس جديد بدل توسيع
   دلالة السجل القديم. وإضافة حقل `baseline` إلى بوابة غير مقاسة مرفوضة.

## فضاء المرشحين والقياس

`measure_candidates` يعد هويات سجل محدود مزود له. الهوية متميزة بحسب
المعرف المعلن؛ لا يثبت أن معرفين مختلفين يمثلان معنيين مختلفين. لذلك
يُرفض تكرار المعرف بدل محوه أو الكتابة فوقه. لا تستنتج الأداة أدوارًا
نحوية أو معاني من الأرقام أو البصمات.

الحالات المعلنة هي `licensed` و`pending` و`refuted`. يبقى المعلق في
المجموعة المعدودة: `remaining = licensed ∪ pending`. القياس لا يراجع
صحة هذه الحالات؛ هذه مهمة فاحص الطبقة المنتج لها.

يقاس `log2(|remaining|)` بوصفه **هارتلي للسجل المقدم**، لا أنتروبيا جميع
القراءات العربية. المخرج `COUNTED_SUPPLIED_LEDGER` و
`EXACT_FOR_SUPPLIED_LEDGER` لا يصادقان على تمام التعداد اللغوي. سواء أعلن
المنتج `DECLARED_COMPLETE` أو `PARTIAL` أو `RESOURCE_LIMIT`، يبقى
`linguistic_completeness_verified=false`. يظل اسم حالة الاستنفاد محفوظًا.

الفارغ يعطي عددًا صفريًا و`ledger_hartley_bits=null`، لا صفر بت ولا إجماعًا
ولا نفيًا لغويًا. الواحد يعطي صفر بت وصفر زيادة في سلطة الدليل. لا تستعمل
احتمالات مفترضة ولا درجة ثقة أو جودة مركبة.

يحمل كل قياس توقيعًا: المجال ونوع العنصر وعلاقة تمييزه والوحدة، وربط المصدر،
ونسخ القانون والنحو والمعجم والعرف والسياق والشواهد وحدود التعداد. فحص
صيغة hash والمواضع ليس فحصًا لبايتات المصدر؛ لذا يبقى
`source_binding_verified=false`. لا تقارن مقدارين مختلفي التوقيع كأن
انخفاضهما تحسن. توسيع المعجم أو سحب الشاهد قد يزيد البدائل.

## التشغيل

من جذر المستودع:

```bash
PYTHONPATH=src:. python -B -m tools.entropy_framework validate
PYTHONPATH=src:. python -B -m tools.entropy_framework report
PYTHONPATH=src:. python -B -m tools.entropy_framework measure candidates.json
PYTHONPATH=src:. python -B -m unittest discover -s tests -p test_entropy_framework.py -v
```

يمكن تحديد سجل آخر عبر `--registry path.json`. نجاح أمر CLI يعني نجاح
فحص البيانات أو حسابها فقط؛ المدخل غير الصالح يخرج برمز 2 وحالة
`INVALID_INPUT`. لا تعدل الأوامر سجل العمل ولا تغير قوانين NABT.

ميزانية قراءة JSON هي8 MiB و4096 رقمًا عشريًا لكل عدد صحيح، دون احتساب
إشارة السالب. تجاوز الميزانية أو حد التعشيق في المفسر يخرج برمز3 وحالة
`RESOURCE_EXHAUSTED`، ولا يصنف رفضًا لغويًا أو مدخلًا خاطئ البنية. تبقى
رسائل الخطأ نفسها UTF-8 صالحة حتى إذا احتوى المدخل Unicode غير صالح.

مثال مدخل قياس مصطنع — صفرا البصمة لا يمثلان مصدرًا موثقًا:

## المراجعة وصلاحية الدليل

يتضمن سجل الدليل النطاق وهوية المجموعة والمقيم والكود والمترجم ونتائج
الفحوص المطلوبة. عند تغير عنصر مؤثر يجب مراجعة الأدلة التابعة وإعلان
التقادم؛ الأداة الحالية لا تستنتج التقادم تلقائيًا من المستودع ولا تصادق
على hashes التنفيذ. تحفظ النتائج التاريخية ويعاد تشغيل العقود المتأثرة.

يظل NABT مستقلًا عن إصدار Mashru. ينقل تكامل Mashru إصدارًا معينًا من
NABT بعقد توافق منفصل. لا يغير هذا الإطار النواة أو `src/` أو الجداول
المولدة أو المراجع الذهبية التاريخية. أدلة الاختبارات التنظيمية ليست
أدلة على صحة العربية أو الواقع.
