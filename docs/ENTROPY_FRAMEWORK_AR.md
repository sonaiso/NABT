## المسؤوليات وحالات التقرير

يربط السجل ستة أدوار وثماني طبقات و25 مهمة وسبع بوابات:

| البوابة | نطاقها وحالتها المصرح بها |
|---|---|
| G0 | اتصال المصدر والشهادة العام؛ غير مقاس |
| GM | عقد قياس السجل المحدود العام؛ غير مقاس |
| G1 | PCV1 ومجموعة 200؛ قياس محفوظ PASS، والمراجعة محجوبة بالاعتمادات |
| G2 | الوضع والعرف ومجموعة 120 المخططة؛ غير مقاس |
| G3 | الاستقامة والنفي والحصر في 80 زوجًا مخططًا؛ غير مقاس |
| G4 | دورة حياة الشاهد ومجموعة 40 المجمدة؛ غير مقاس |
| GR | إصدار محدود متصل بفحوصه المطلوبة؛ غير مقاس |

يحمل `measurement` حالة `NOT_MEASURED/MEASURED/STALE/NOT_APPLICABLE`،
ونتيجة `PASS/FAIL` عند وجود قياس، ومعرفات أدلة، وسببًا عند التقادم أو
عدم الانطباق. يلزم القياس الحالي تطابق البوابة والنطاق وهوية المجموعة
المجمدة. يلزم PASS فحوص معلنة غير فارغة بلا فشل أو تجاوز أو مفقود.
يجوز حفظ قياس فاشل، أو دليل متقادم بهويته القديمة؛ لا يفتحان المراجعة.

يحسب التقرير `admission.readiness` بصورة مستقلة:

- `BLOCKED_MEASUREMENT` إذا غاب قياس حالي معلن ناجح.
- `BLOCKED_DEPENDENCIES` إذا نجح القياس وبقي اعتماد مباشر غير جاهز.
- `READY_FOR_REVIEW` إذا اتسقت شروط القياس واعتماداته المعلنة.

تبقى `admission.decision=NOT_EVALUATED` في الحالات الثلاث.
`READY_FOR_REVIEW` لا يعني اعتماد البوابة أو صحة أدلتها. يمكن أن تكون
كل بيانات تشغيل مصطنع متسقة؛ لذا يبقى `evidence_verified=false`
و`semantic_authority=NONE` و`release_admission=NOT_EVALUATED`.
يرفض الفاحص تمرير حقول سلطة داخل البوابة أو القياس أو سجل الدليل.

لكل مهمة `scope` و`parent_task_id`. علاقة الأبوة تنظيمية، و`depends_on`
للاعتمادات اللازمة للتسليم. تفحص الدورات والمراجع في كليهما. تتطلب
`READY/DELIVERED` تسليم الاعتمادات الصريحة، وتسليم الأب يتطلب تسليم
أبنائه المسجلين؛ لكن تسليمهم لا يغلقه تلقائيًا.

T02 وT04 أبوان مفتوحان، وشهادة PCV1 وبروتوكوله مسلّمان في
T02-PCV1/T04-PCV1. تعتمد T07/T08 هذين النطاقين. يعتمد عد السجل T05
عقد المرشح T03؛ لا يدعي توثيق المصدر. حذفت تبعية T10 لـT06 لأن تقييم
لقطة PCV1 الثابتة لم ينفذ سحب الشواهد؛ بقي T06 مفتوحًا بدل اختلاق إنجازه.

T04-LC1 يسجل تسليم البروتوكول والذهب، وT15-LC1 يسجل **عقد** الشاهد
المؤهل المجمد. T06-LC1 قيد المراجعة بعد التنفيذ، وT16-LC1 مخطط للتقييم ولم يسلم.
T11-PREP1 يسجل فهرس المصادر وإسقاطات الأوضاع الموجودة؛ لا يثبت استعمالًا
جديدًا أو 120 حالة. الآباء T06/T11/T15/T16 تبقى مفتوحة. استعادة Ω العامة
وتوسعة الزمن والوحدات والإحالة الخارجية والدمج الدلالي مع G2/G3 أهداف
لاحقة، ولا يحقق هذا الجزء N6-ب أو شرط N2 ذي400 واقعة.

### إضافة نتيجة مقاسة

1. تحفظ النتيجة الأولى وfreeze وأمر التشغيل في مسار دليل مستقل، ثم
   تحفظ الإصلاحات المكشوفة منفصلة. لا يعدل الذهب أو المصدر أو baseline.
2. يضاف سجل إلى `evidence_records` بمعرف فريد، والبوابة والنطاق نفسيهما،
   وهوية المجموعة والمقيّم والمترجم والكود ونتائج الفحوص المطلوبة.
   لا يقرأ الفاحص مرجع الملف أو يصادق على بصمته أو يصدق سلطة ناشره.
3. تربط `gate.measurement` النتيجة الحالية، وتصبح القدرة `EVALUATED`
   بمراجعها المعلنة. لا يشترط اكتمال الاعتمادات لحفظ القياس نفسه؛ تعكس
   `admission` عوائق المراجعة دون قرار قبول.
4. تحفظ المقامات بوحداتها، وتبقى المهام الأم مفتوحة إذا تجاوزت الجزء.
   إن تغير عقد القياس أو بياناته تسجل الهوية الجديدة صراحة ويحفظ السابق؛
   عند تقادم نتيجة يسجل `STALE` مع السبب، ولا يحذف التاريخ.

## فضاء المرشحين والقياس

`measure_candidates` يعد هويات سجل محدود مزود له. الهوية متميزة بحسب
المعرف المعلن؛ لا يثبت أن معرفين مختلفين يمثلان معنيين مختلفين. لذلك
يُرفض تكرار المعرف بدل محوه أو الكتابة فوقه. لا تستنتج الأداة أدوارًا
نحوية أو معاني من الأرقام أو البصمات.

الحالات المعلنة هي `licensed` و`pending` و`refuted`. يبقى المعلق في
المجموعة المعدودة: `remaining = licensed ∪ pending`. القياس لا يراجع
صحة هذه الحالات؛ هذه مهمة فاحص الطبقة المنتج لها.

يقاس `log2(|remaining|)` بوصفه **هارتلي للسجل المقدم**، لا أنتروبيا جميع
القراءات العربية. المخرج `COUNTED_SUPPLIED_LEDGER` و
`EXACT_FOR_SUPPLIED_LEDGER` لا يصادقان على تمام التعداد اللغوي. سواء أعلن
المنتج `DECLARED_COMPLETE` أو `PARTIAL` أو `RESOURCE_LIMIT`، يبقى
`linguistic_completeness_verified=false`. يظل اسم حالة الاستنفاد محفوظًا.

الفارغ يعطي عددًا صفريًا و`ledger_hartley_bits=null`، لا صفر بت ولا إجماعًا
ولا نفيًا لغويًا. الواحد يعطي صفر بت وصفر زيادة في سلطة الدليل. لا تستعمل
احتمالات مفترضة ولا درجة ثقة أو جودة مركبة.

يحمل كل قياس توقيعًا: المجال ونوع العنصر وعلاقة تمييزه والوحدة، وربط المصدر،
ونسخ القانون والنحو والمعجم والعرف والسياق والشواهد وحدود التعداد. فحص
صيغة hash والمواضع ليس فحصًا لبايتات المصدر؛ لذا يبقى
`source_binding_verified=false`. لا تقارن مقدارين مختلفي التوقيع كأن
انخفاضهما تحسن. توسيع المعجم أو سحب الشاهد قد يزيد البدائل.

## التشغيل

من جذر المستودع:

```bash
PYTHONPATH=src:. python -B -m tools.entropy_framework validate
PYTHONPATH=src:. python -B -m tools.entropy_framework report
PYTHONPATH=src:. python -B -m tools.entropy_framework measure candidates.json
PYTHONPATH=src:. python -B -m unittest discover -s tests -p test_entropy_framework.py -v
```

يمكن تحديد سجل آخر عبر `--registry path.json`. نجاح أمر CLI يعني نجاح
فحص البيانات أو حسابها فقط؛ المدخل غير الصالح يخرج برمز 2 وحالة
`INVALID_INPUT`. لا تعدل الأوامر سجل العمل ولا تغير قوانين NABT.

ميزانية قراءة JSON هي8 MiB و4096 رقمًا عشريًا لكل عدد صحيح، دون احتساب
إشارة السالب. تجاوز الميزانية أو حد التعشيق في المفسر يخرج برمز3 وحالة
`RESOURCE_EXHAUSTED`، ولا يصنف رفضًا لغويًا أو مدخلًا خاطئ البنية. تبقى
رسائل الخطأ نفسها UTF-8 صالحة حتى إذا احتوى المدخل Unicode غير صالح.

مثال مدخل قياس مصطنع — صفرا البصمة لا يمثلان مصدرًا موثقًا:


## المراجعة وصلاحية الدليل

يتضمن سجل الدليل النطاق وهوية المجموعة والمقيم والكود والمترجم ونتائج
الفحوص المطلوبة. عند تغير عنصر مؤثر يجب مراجعة الأدلة التابعة وإعلان
التقادم؛ الأداة الحالية لا تستنتج التقادم تلقائيًا من المستودع ولا تصادق
على hashes التنفيذ. تحفظ النتائج التاريخية ويعاد تشغيل العقود المتأثرة.

يظل NABT مستقلًا عن إصدار Mashru. ينقل تكامل Mashru إصدارًا معينًا من
NABT بعقد توافق منفصل. لا يغير هذا الإطار النواة أو `src/` أو الجداول
المولدة أو المراجع الذهبية التاريخية. أدلة الاختبارات التنظيمية ليست
أدلة على صحة العربية أو الواقع.
