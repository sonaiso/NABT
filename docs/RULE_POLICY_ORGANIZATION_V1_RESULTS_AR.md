# نتيجة تنظيم القواعد والسياسات في NABT

نقطة الأساس `181dec466ccfad5b6a63ec9750f149ea58829eda`، بعد دمج عقود
الشرح في PR 63. ثُبتت المواصفة والقبول المستقل قبل التنفيذ في
`5dca9ada9b251400036db5359cb55e938ff1dec4`، ثم ثُبت التنفيذ الذي فُحص
في `9815d4a5ae3aa562500bc7a2b26a4956fd0f646a`.

## النتيجة التنفيذية

أصبح `rule_contract` و`evidence_freshness` عقدين مفحوصين داخل إطار
المشروع القائم. أُضيف العرض الاختياري `reuse --organization`، الذي
يصل الأدوار ومراحل الاستعمال بمراجعها الفعلية في فهرس المصدر وفهرس
البراهين وعائلات الاستعمال وعقود الإطار وبواباته.

يحفظ العرض 11 سجل إحالة و5 علاقات تنظيمية، ويعيد جميع سجلات الفهرس
اللغوي الـ125. موضوعا إحالة مباشران مصنفان، و123 سجلًا غير مصنف
في هذه الدفعة. التصنيف التنظيمي لا يثبت شمول العربية أو تنفيذ كل
عملية؛ كما أن غيابه لا يثبت غياب تنفيذها.

لا تنشئ الدفعة محرك استدلال أو جدول قوانين أو سجل مبرهنات ثانيًا.
تستخدم [منشئ الفهرس القائم](../tools/grammar_catalog/catalog.py) و
[فهرس إعادة الاستعمال](../tools/entropy_framework/reuse.py). يشرح
[التنظيم المنفذ](../tools/entropy_framework/organization.py) حدود العرض،
وتشرح [خطة التنظيم](NABT_RULE_POLICY_ORGANIZATION_AR.md) صلته بدورة
التكوين والاعتماد والتطبيق والمراجعة.

## ما الذي صار قابلًا للفحص؟

| الالتزام | السلوك المنفذ |
| --- | --- |
| اكتمال العقد الأساسي | رفض غياب أحد العقدين أو نقص مفرداته أو استبدال سياسته؛ قبول إعادة ترتيب المفردات مع حفظ ترتيب الإدخال وهويته |
| نوع القاعدة أو السياسة | سبعة أدوار مستقلة عن الأنواع الخمسة للعملية وعن مراحل الاستعمال الأربع |
| المرجع | حل مطابق لهوية صاحب موجود؛ رفض الأسماء غير الموجودة وحقول المصدر والنسخة والنطاق المفروضة من المستدعي |
| النطاق | حفظ نطاق صاحب المرجع إلى جانب ملاحظة النطاق المؤلفة؛ لا يثبت العرض تساويهما أو احتواء أحدهما للآخر |
| اعتماد التبرير | رفض الدورة في اجتماع علاقات التبرير والمتطلبات، مع حفظ دورات الإحالة والاستدلال والتعارض بوصفها بيانات |
| المصدر المتعارض | حفظ `textual_discrepancy` في سجل النون قبل الباء بجانب مؤثره المشروط؛ لا تسويتهما إلى علامة نجاح واحدة |
| هوية البيانات | اشتقاق بصمة السجل من البايتات نفسها التي حُللت، ورفض تغيرها أثناء بناء التقرير |
| عدم التنفيذ | لا تشغيل لمراجع البيانات أو محقق أصلي من هذا العرض؛ سلطة المعنى والفعل `NONE` |
| حدود الموارد | ميزانيات معلنة؛ التجاوز `RESOURCE_EXHAUSTED` وخروج 3، والمدخل غير الصالح خروج 2 |

السجلات موزعة إلى ثلاثة تعريفات/أنواع، وطريقة تكوين واحدة، وقاعدة
تفسير لغوي واحدة، وترخيص استدلال واحد، وأربع سياسات قبول/مراجعة
للدليل، وبوابة تقييم واحدة. دور سياسة الفعل ممثل في العقد، لكن لا
توجد إحالة تمنح سلطة فعل في هذه الدفعة.

`RESOLVED` يعني أن الإحالات حُلّت إلى أصحابها. جميع حقول الوقائع
`formation/adoption/application/revision` تبقى `NOT_OBSERVED`.
ويختلف هذا عن `DECLARED_REFERENCES_NOT_RESOLVED` في فحص البنية
العادي، وعن `NOT_DECLARED` عند غياب التنظيم الاختياري.

## ما ثبت من القدرات الموجودة قبل التعديل؟

حُفظت [ست تجارب أساس قابلة للإعادة](../evidence/rule_policy_organization_v1/baseline_capability_probe.json)
و[برنامج تشغيلها](../evidence/rule_policy_organization_v1/baseline_capability_probe.py):

| التجربة | الملاحظة الفعلية |
| --- | --- |
| تكوين حارس محدود ومراجعة شواهده | 8 ثم 4 ثم 2 ثم 1 مرشح؛ سحب شاهد أعاد مرشحين، وإعادته أعادت المرشح والمراجعة الأصليين؛ توسيع اللغة أبقى 5 مرشحين للشواهد نفسها |
| تعريف وتطبيق على فرد | دعم مع الشواهد الكاملة؛ فرد جديد بلا شاهد بقي مجهولًا؛ سحب الحالة أوقف الدعم وأبطل الشهادة القديمة |
| البحث وحد المطابقة الخارجية | قبول مراجعة اللقطة عند الرتبة 2 وإعادة فحصها؛ طلب المطابقة الخارجية بقي مؤجلًا |
| الدليل والنقيض والدافع الخفي | دعم ثم تعارض عند إضافة شاهد مقابل؛ الدافع الخفي بقي مجهولًا، مع ثلاث عمليات تحقق أصلية |
| دورة الأدلة | دعم ثم مجهول ثم دعم؛ الحلقة المتغيرة رفضت التقرير التاريخي |
| ترتيب القواعد | الجدولة أبقت جميع المعرفات المنصبة رغم الترتيب المقترح والمعرفات المكررة أو المجهولة |

هذه تجارب هندسية مكشوفة، وليست اختبار تعميم محجوبًا. تستخدم أدوات
المشروع الموجودة، ولم تبن Lean من جديد. وتبين لماذا يحتاج اعتماد
المرشح إلى مستند إضافي: اتفاق الباقي مشروط بلغة الفرضيات، وصحة
التنبؤ بالنسبة إلى نموذج لا تثبت صدق النموذج في الخارج.

## التحقق المستقل والانحدار

| المقام | النتيجة |
| --- | --- |
| مصفوفة القبول المثبتة قبل التنفيذ | 14 مجموعة، جميعها منفذة وناجحة؛ لا تخطٍّ |
| اختبارات المراجعة المضافة | 4: ترتيب المفردات، الخيار الفارغ، تغير بايتات السجل، وحد الموارد |
| اكتشاف اختبارات إعادة الاستعمال | 48/48: الثلاثون السابقة والثمانية عشر الخاصة بهذه الدفعة |
| الإطار وأصحاب فهرس القواعد | 98/98 بعد ضبط `PYTHONPATH`؛ لا تخطٍّ |
| المراجعة المستقلة المحدودة | 18 فحصًا، جميعها ناجحة؛ مقام منفصل عن طرق unittest |
| حفظ الملفات المجمدة | 90 اعتمادًا و99 ملف تنفيذ مطابقًا؛ لا تعديل على `Makefile` أو سير CI الرئيسي |
| الفهرس المترجم القائم | المدخلات مطابقة؛ 82 وحدة و1605 تصريحات؛ لا تجميع Lean جديد في التحقق المحلي |
| حد الاستيراد الساكن | فحص `code_entropy --check` ناجح؛ 305 ملفات في مقام الجرد الساكن |

تشمل اختبارات القبول استبدال بايتات المصدر داخل أداة القراءة في
عملية الاختبار، وتغيير نسخة مؤقتة من السجل، وحقن أوامر وحقول سلطة،
ودورة مختلطة الأنواع، ومراجع معلقة، ومحاولات استبدال ملف تقرير
موجود. بقيت المدونة الأصلية والسجلات المنصبة دون تعديل.

حُفظت المحاولات الأولى كما وقعت. نجحت المجموعات الأربع عشرة في
أول تشغيل. وكشفت مراجعة لاحقة أن `--run ''` عومل كغياب للخيار،
فصُحح واختُبر. أما أول تشغيل مجمع لأصحاب الفهرس فسجل 87 حالة
تشغيل، منها خطأ تحميل وحدة لأن `nabt` لم يكن في مسار Python؛
لم تنفذ عندها اختبارات وحدة الاسترجاع. نجحت الإعادة الكاملة
ذات 98 اختبارًا بعد ضبط البيئة دون تغيير الشيفرة.

يحفظ [سجل التحقق](../evidence/rule_policy_organization_v1/validation/verification_summary.json)
هوية الشيفرة والاختبارات والمواصفة والقبول، والسجلات الأولى، وإعادة
التشغيل. لا تضاف أعداد التشغيلات المكررة إلى 146 طريقة الاختبار
المتميزة في المجموعتين النهائيتين. فحوص GitHub على رأس النشر
تظل مرحلة منفصلة عن هذا السجل المحلي.

## الاستعمال والاستمرار

```sh
python -m tools.entropy_framework reuse --organization --summary
python -m tools.entropy_framework reuse --organization \
  --output artifacts/local/rule-policy-map.json
python -m tools.entropy_framework validate
PYTHONPATH=src:. python -B -m unittest discover -s tests \
  -p 'test_proof_reuse*.py' -v
```

يحفظ `--output` التقرير الكامل ويشترط اسم ملف جديد. لا يجمع وضع
التنظيم مع تحديد عائلة أو وحدة أو تشغيل مدخل. يبين
[التقرير المحفوظ](../evidence/rule_policy_organization_v1/validation/organization_report.json)
المراجع والنطاقات والبقايا، ويتوفر
[ملخصه](../evidence/rule_policy_organization_v1/validation/organization_summary.json).

أُدرج المدخل في `AGENTS.md` و`CLAUDE.md` ودليل الاستعمال والخطة،
وأُلحقت الشيفرة والاختبارات والوثائق بعائلة الاستعمال الحالية.
تكتشف بوابة `NABT capability reuse` الاختبارات الجديدة عبر النمط
الموجود؛ لم تُنشأ بوابة موازية.

بعد التنظيم يمكن أن يتقدم مساران: وصل مرشح محدود بمستند اعتماد
مستقل وشاهد تطبيق جديد؛ وإظهار شروط المؤثرات وموانعها وأمثلتها
بجانب إيصالاتها، ثم نقل شجرة التطبيق اللغوية إلى `CertifiedBridge`.
جسر الاعتماد، وحفظ شجرة التطبيق، وتحقيق المناط الخارجي ما زالت
التزامات صريحة. لا ينجزها تصنيف العقد أو نجاح حل مرجعه.
