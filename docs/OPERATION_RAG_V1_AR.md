# RAG للعمليات والحسابات في NABT — الإصدار الأول

## المنفذ وحدوده

يضيف `tools.grammar_catalog rag` استرجاعًا لبطاقات العمليات، وربطًا بوسائط
محددة، وتنفيذًا لأصحاب العقود الموجودين، وجوابًا عربيًا مرتبطًا بالنتيجة
والشيفرة. يولّد العارض الجواب بقوالب حتمية. لا يوجد اتصال خفي بنموذج لغوي،
ولا تدريب عصبي جديد، ولا قاعدة متجهات مفروضة على هذا الجرد الصغير.

راجعت الشيفرة على أساس `4c3734cbb0a54de984980317698b7830214e86e5`
بعد دمج #78. وأعيد تشغيل جرد إعادة الاستعمال والتنظيم. المرجع الرسمي
المختار يتضمن 1608 تصريحات في 83 وحدة؛ هذه أعداد الجرد، وليست قياسًا
لفهم العربية. لا يعيد هذا التغيير إنشاء قانون أو فهرس براهين أو مفسر تعلم.

في الفحص المباشر، محو الحركات في إسقاط البحث الموجود يجعل «كَتَبَ/كُتِبَ»
متساويين في مفردات البحث، مع اختلاف ترميزهما العددي. كما أعاد قارئ الاشتقاق
`DEFER`، ولم يجد قارئ الشخص دون نموذج معجمي مرشحين لأمثلة «قُمْتُ/قُمْتَ/قُمْتِ».
أُبقيت هذه الحدود في التنفيذ. نجاح إعادة تقرير مؤجل لا يحوله إلى حكم مثبت.

## المسار

1. يتحقق `current_catalog` من فهرس Lean المثبت ومطابقته للمصادر الحالية.
2. تُستخرج وحدة الدالة بواسطة AST: مسار، رمز، أسطر، نص أصلي، وبصمة ملف.
   تشمل البطاقة عقد المدخلات، الافتراضات الافتراضية، النطاق، الموانع،
   والتصريحات ذات الصلة في **الوحدة المالكة**. هذه علاقة توثيقية، ولا تدعي
   أن مبرهنات الوحدة تبرهن صحة المهايئ الجديد أو تنقيح Python إلى Lean.
3. يعاد استعمال BM25 الموجود، ويُدمج ترتيبه مع تطابق المفردات الحرفي بواسطة
   RRF-60. القناة الحرفية تحتفظ بالحركات والترتيب ومواضع Unicode وUTF-8.
   تقبل واجهة `OperationSearchIndex.search` اختياريًا درجات متجهات ذات
   نموذج وإصدار وبصمة فهرس ووصفة إدخال مثبتة، مع تحقق الغلاف الموجود.
   لم تُدرّب أو تُقيّم متجهات جديدة في هذا الإصدار.
4. يأتي اختيار العملية من طلب مصنف أو صيغة أمر كاملة محدودة، ويُعلن مصدره.
   أعلى نتيجة بحث لا تصبح إذنًا بالتنفيذ. الحد `limit` للعرض فقط؛ العملية
   المحددة صراحة تُستعاد من الفهرس الكامل حتى إذا غابت عن النتائج المعروضة.
5. ينفذ عامل منفصل قائمة سماح ثابتة عبر مدخل `grammar-catalog` الموجود.
   لا يشغّل نصوص البطاقات ولا مسارات يختارها الطلب. تُزال متغيرات تجاوز
   المسارات `NABT_*` في العامل ليستعمل أصحاب العقود المثبتين.
6. يعاد تقرير المالك كاملًا، بما فيه البدائل والموانع وحالة الإرجاء، ثم يولّد
   شرح عربي مؤشّر إلى `/execution` وموضع الدالة. فحص `--verify` يحتاج
   **طلبًا أصليًا مستقلاً** ويعيد التنفيذ ويقارن التقرير كله، بما فيه الشرح
   ودرجات الاسترجاع. البصمة وحدها ليست فحصًا للنتيجة أو تصديقًا للمصدر.

| العملية | الوسائط الرئيسية | صاحب الحساب أو القراءة |
|---|---|---|
| `encode`, `decode` | `text` أو `number` كسلسلة | `alphabet` و`codec` و`cli.numeric_payload` |
| `contrast` | `texts` من 2 إلى 8 ألفاظ | الترميز الموجود لكل لفظ دون استكمال حركات |
| `analyse` | `text`, `mode`, `start_state` | `Machine.analyse` |
| `effect`, `compose_effects` | `text` أو `texts` | `Machine.effect` و`compose_effects` على الحالات الـ97 |
| `count` | `weight`, `mode`, `start_state` | `Machine.count` |
| `rank`, `unrank` | النص أو الوزن والرتبة | `Machine.rank` و`Machine.unrank` |
| `derivation` | النص والمصدر والنطاق والملف المحدود | `read_derivation` و`verify_derivation` |
| `person` | `text` | `person_candidates`؛ دون افتراض معجم غير مقدم |
| `program` | `request` بعقد المفسر الموجود | `compile_request` و`execute_program` و`verify_execution` |
| `lesson` | `lesson` بعقد الدرس الموجود | `run_lesson` و`verify_lesson` |

لا تصبح الآثار العددية للكلمات شهادة نطق، ولا تصبح رتبة الشكل رتبة صدق.
`mode=waqf` و`start_state=0` افتراضيان معلنان للعمليات التي تقبلهما،
ويظهران في `effective_inputs`. يحتفظ مسار الدرس بفواحِصه الأصلية؛ غياب
الملفات التنفيذية لـLean يبقى نقصًا ظاهرًا في تقريره.

## الاستعمال

من جذر المستودع، مع Python 3.12 على Linux، ودون تبعيات جديدة:

```sh
export PYTHONPATH=src:.
python -m tools.grammar_catalog operations 'تركيب الآثار'
python -m tools.grammar_catalog rag --request examples/operation_rag/contrast.json --output /tmp/nabt-rag.json
python -m tools.grammar_catalog rag --request examples/operation_rag/contrast.json --verify /tmp/nabt-rag.json
python -m tools.entropy_framework reuse --run grammar-catalog -- rag --request examples/operation_rag/learning.json
make -f Makefile -f integrations/grammar_catalog.mk operation-rag
```

طلب مصنف:

```json
{
  "schema": "nabt.operation-rag.request.v1",
  "query": "احسب عدد الأشكال ذات الوزن أربعة في الوقف",
  "operation": "count",
  "inputs": {"weight": 4, "mode": "waqf", "start_state": 0},
  "limit": 3
}
```

يمكن حذف `operation` و`inputs` معًا عند استعمال واحدة من الصيغ الكاملة:

```text
رمّز «كَتَبَ»
رمز «كَتَبَ»
احسب أثر «كَتَبَ»
حلل شكل «كَتَبَ»
حلل اشتقاق «كَاتِب»
قارن «قُمْتُ» و«قُمْتَ» و«قُمْتِ»
احسب عدد الأشكال للوزن 4
```

الصيغ لا تفهم العربية الحرة ولا تستكمل الحركات. السؤال الآخر يعيد
`NEEDS_REQUEST` وبطاقات العمليات. «قمتُ» تبقى ناقصة التشكيل تحت A116؛
لا تُستبدل تلقائيًا بـ«قُمْتُ». نص السؤال ووسائط الطلب المصنف محفوظان
منفصلين؛ `CALLER_TYPED_REQUEST` لا يثبت أنه استنبط قصد السؤال الحر.

## الهوية والموارد والحالات

- تحفظ هوية اللقطة ملفات الشيفرة والبيانات المثبتة والفهرس الرسمي، ومصادر
  التوثيق ومراجعة المنهاج والملفات التنفيذية المتاحة. التغير، بما فيه الإضافة
  والحذف، يبطل إعادة التقرير القديم. هذه سياسة محافظة؛ قد يبطل تعديل توثيقي
  تقريرًا أيضًا. يجب إعادة تشغيل العملية بعد تحديث الشيفرة المثبتة.
- لا يوجد تخزين مؤقت للنتائج الدلالية. يعاد برنامج المصدر والسحب والتعلم
  في كل طلب. ليس هناك ادعاء بتسريع الحساب أو خفض التكلفة قبل قياس مستقل.
- الطلب 128 KiB، والتقرير 8 MiB، والسؤال 16 KiB. تُرفض مفاتيح JSON
  المكررة، والأعداد غير المنتهية، و`bool` في المواقع العددية، والحقول الزائدة.
  تُنقل الأعداد الكبيرة كسلاسل عشرية/سداسية معلنة بدل فقدان دقتها في JSON.
- العامل: مهلة جدارية 30 ثانية، CPU عشرون ثانية، ذاكرة عنوانية 1 GiB،
  وحد ملف خرج 8 MiB. تُقتل مجموعة العمليات عند انتهاء المهلة. هذه حدود
  تشغيل على Linux، وليست صندوقًا لتشغيل شيفرة أجنبية؛ الشيفرة المتاحة
  محصورة في أصحاب العقود المثبتين.
- `EXECUTED` يعني عودة المالك، لا قبول الدلالة. راجع `owner_result` و
  `owner_verification`. `OWNER_ERROR` يحفظ خطأ المالك الأصلي، و
  `RESOURCE_LIMIT` و`WORKER_ERROR` لا يعنيان بطلان اللفظ. `VERIFIED_REPLAY`
  يثبت تطابق الإعادة مع نفس الطلب والنسخة، ولا يغلق التزامات المالك المؤجلة.
- واجهة CLI تخرج بـ0 للتقرير المنفذ أو خطأ المالك المنقول، وبـ3 لنقص الطلب
  أو فشل العامل/الموارد، وبـ2 للمدخل المشوه أو فشل فحص التقرير. لذلك لا
  يكفي كود الخروج وحده للاستدلال على ترخيص لغوي.

## القبول والقيود الباقية

تغطي `tests/test_operation_rag.py` استرجاع العمليات، والهوية الحرفية،
والترميز بأعداد مرجعية، وجذور إضافية، وتركيب الأثر مقابل مرجع الحروف
المستقل على 97 حالة، وعد الأشكال الصغيرة، وفصل الوقف والوصل، وسحب
شاهد التعلم وإعادته، ووصل الدرس، وغياب الفاحص، وتغيير المصدر، والتلاعب
بالناتج والشرح والترتيب والطلب، وحد المهلة، والنقل عبر CLI.

هذه اختبارات تطوير مكشوفة. لا تثبت تعميم نموذج عصبي على جذور محجوبة،
ولا اكتساب معنى الوقوع، ولا دقة قارئ عربي حر. لم تُغيّر النواة ولا قوانين
Lean ولا فهارسها. فحوص البناء الرسمي والمطابقة الحالية تبقى مالكة
لشهادة Python/Lean في نطاقاتها؛ لا يستبدلها نجاح اختبارات RAG.

أُضيفت هذه الاستعمالات إلى سجل `reuse` الموجود وإلى بوابة CI القائمة.
تسمح واجهة الوسائط بإضافة مقترِح لغوي لاحقًا، على أن يقاس مستقلاً وتبقى
حدود الطلب وفحص المالك وإعادة المصادر نافذة. توسيع العمليات أو بناء
فهرس دائم يحتاج قياسات استرجاع وكمون ونقص مستقلة قبل ادعاء التحسن.
