## حدود البحث القابلة للمراجعة

- المجموعة هي المستودعات الـ24 التي أعادها البحث المتاح للاتصال عن الهويتين،
  وليست جميع مستودعات GitHub أو ضمانًا برؤية كل مستودع خاص. لم يحتفظ هذا
  الجرد باستجابات صفحات البحث الأولي؛ لذلك لا يستطيع إثبات اكتمال استكشاف
  المستودعات خارج القائمة المعطاة. القائمة الأصلية محفوظة كما وصلت.
- استُعمل الفرع الافتراضي `main` ثم ثُبّت commit وtree SHA. لم تُفحص الفروع
  الأخرى أو كل التاريخ. رأس NABT المفهرس هو
  `ccd444551a95b51532eb316f0a39a401f7edc8ed`، وليس رأس فرع هذا التغيير.
- طلب Git tree التكراري واحد لكل مستودع، وكل رد أبلغ `truncated=false`؛
  التحقق هنا من عدم البتر لا من pagination بحث المستودعات. لا تُتبع محتويات
  submodule من دون جرد منفصل.
- فُحصت كل أسماء المسارات، ثم حُددت ملفات نصية مرشحة بحد مليون بايت، إضافة
  إلى README/LICENSE/MANIFEST وفهارس المصادر؛ استُثنيت تبعيات وملفات ثنائية
  وأغلب الملفات المضغوطة. استُثنيت النصوص التراثية العشرة المذكورة من حد
  الحجم بقرار صريح. بقي **27 مرشحًا بفحص المسار فقط**.
- المسح كامل داخل كل ملف مختار لكنه بحث كلمات لا قراءة فقهية لكل سطر؛
  حُفظ عدد الأسطر المطابقة وأول ثلاثة أمثلة لكل فئة. بلغ عدد الملفات ذات
  إصابة مسارية أو نصية **513**. هذا العدد يشمل إصابات كاذبة؛ مثل
  `WasItself` الذي يطابق `wasit`، و«الخصائص المصدرية» التي لا تعني كتاب
  الخصائص. الجدول السابق هو مراجعة مختارة لمعنى الإصابات.
- طلبا raw لملفين فارغين في sanadcom رفضتهما الواجهة؛ أُعيد التحقق عبر
  Git Data API من كائن الملف الفارغ `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`.
  لم يبق فشل جلب في مجموعة الملفات الـ703. عدم إصابة كلمة لا يثبت عدم
  وجود المصدر داخل بقية الملفات غير المقروءة.
- لم تُستعمل رموز وصول وردت في المحادثة، ولم تُحفظ بيانات اعتماد. الجلب
  استخدم اتصال GitHub المتاح وطلبات عامة للمصادر المثبتة.

## إعادة الفحص

فحص اتساق الشجر المحفوظة، وعضوية كل blob، وأعداد الملفات وحدود أسطر الشواهد:

```bash
python evidence/arabic_completion_v5/repository_survey/verify_pinned_sources.py
```

أُجري هذا الفحص ونجح: 24 شجرة، 703 ملفات نصية ممسوحة، دون خطأ اتساق. هذا
فحص دليل الفهرسة، وليس اختبارًا لمحرك العربية ولا إعادة تنزيل بعيدة.

وأُعيد جلب عينة أول ثلاثة ملفات والمصادر الخارجية الأربعة بالسكربت نفسه؛
تطابقت بصماتها جميعًا دون خطأ. النتيجة محفوظة في
[`verification.json`](../evidence/arabic_completion_v5/repository_survey/verification.json).
هذه إعادة جلب سبعة موارد، وليست إعادة جلب جميع الملفات الـ703.

إعادة جلب أول عشرة ملفات أو النصوص الخارجية الأربعة ومقارنة البصمات:

```bash
python evidence/arabic_completion_v5/repository_survey/verify_pinned_sources.py --content --limit 10
python evidence/arabic_completion_v5/repository_survey/verify_pinned_sources.py --external
```

حذف `--limit 10` مع `--content` يعيد جلب الملفات الـ703. السكربت لا يكتب
داخل المستودع، ولا يرسل غير GET، ولا يطلب رمز وصول. يبقى فشل الشبكة أو
حد خدمة GitHub فشل استرجاع، ولا يتحول إلى نفي لغوي أو نتيجة اكتمال.
